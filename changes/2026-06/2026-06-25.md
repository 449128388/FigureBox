### 1. 动态流筛选新增 FULL_PAY / IN_STOCK / ORDER_CANCEL

**解决方案：** 动态流筛选器仅支持 buy/sell/out/order/tag/price 等组合分类，缺少对 FULL_PAY（尾款付清）、IN_STOCK（入库）、ORDER_CANCEL（取消订单）三种具体事件类型的独立筛选。

**实现逻辑：**
- **后端** `get_events` 的 `type_map`：
  - `full_pay` → `['FULL_PAY']`（独立筛选尾款付清事件）
  - `in_stock` → `['IN_STOCK']`（独立筛选入库事件）
  - `order_cancel` → `['ORDER_CANCEL']`（独立筛选取消订单事件）
  - `buy` 从 `['BUY', 'FULL_PAY', 'IN_STOCK']` 改为 `['BUY']`（仅买入）
  - 更新 API 接口文档说明
- **前端** `filterOptions` 新增三个筛选按钮：尾款付清、入库、取消

### 结果
- 用户可按事件类型独立筛选 FULL_PAY / IN_STOCK / ORDER_CANCEL
- `buy` 筛选只显示 BUY 类型事件，不再混入 FULL_PAY 和 IN_STOCK
- 全部动态不受影响，仍然展示所有类型

### 2. 修复 SELL 事件详情页数据字段样式不统一

**解决方案：** SELL 事件详情页中订单号、卖出日期、买家、持有天数四个数据字段的字体颜色与 BUY 事件已统一的样式不一致。

**实现逻辑：**
- 四个数据字段的 `<span>` 新增 `buy-detail-value` CSS 类，与 BUY 事件数据字段样式保持一致
- 卖出价格、成本价格、净利润保持原彩色样式不变

### 结果
- SELL 事件详情页四个数据字段样式与 BUY 事件统一

### 3. SELL 事件标题根据订单状态动态生成

**解决方案：** SELL 事件的动态流标题固定为"「xxxxx」已售出，售价 ¥X（盈利/亏损 ¥X）"，没有根据实际的订单状态（待发货/已发货）区分展示。

**实现逻辑：**
- `record_sell_event` 和 `record_sell_update_event` 新增 `tracking_number` 和 `logistics_company` 参数
- 根据 `status` 字段生成不同标题：
  - "待发货"：`「xxxxx」已完成售出，当前待安排寄出，售价 ¥X（盈利/亏损 ¥X）`
  - "已发货"：`「xxxxx」已完成售出，当前已安排寄出，快递单号 XXXX (物流公司 XXX)`（无数据时用"暂无"替代）
  - 其他状态：保持原有标题格式
- `detail_data` 新增 `tracking_number` 和 `logistics_company` 字段
- 前端 SELL 详情页新增快递单号和物流公司展示

### 结果
- 待发货状态的 SELL 事件标题显示待安排寄出和售价/盈亏信息
- 已发货状态的 SELL 事件标题显示快递单号和物流公司

### 4. 新增分享海报和隐私设置功能

**解决方案：** 收藏家模式头部的[分享海报]和[隐私设置]按钮此前仅显示"功能开发中"的提示，未实现实际功能。

**实现逻辑：**
- **分享海报**：新增 `SharePoster` 组件，支持两种模板（资产概览/极简数据），使用 dom-to-image 生成海报图片并保存
- **隐私设置**：后端新增 `collector_privacy` 表和 CRUD API（GET/PUT /collector/privacy），前端新增 `PrivacySettings` 组件和 `usePrivacy` composable
  - 访问权限：个人主页可见性（公开/仅好友/私密）
  - 数据展示：藏品总数、具体藏品列表、资产金额、本命厂商、动态流（开关控制）
  - 分享设置：海报展示粒度（完整数据/仅统计/仅藏品名）
- 前后端分离：服务层 `collector_privacy_service.py` + API 路由 `privacy.py` + 前端组件化拆分
- 海报生成时根据隐私设置过滤数据

### 结果
- 点击"分享海报"打开海报生成弹窗，可切换模板、生成图片并保存
- 点击"隐私设置"打开隐私配置弹窗，7 项隐私配置可独立控制

### 5. 海报二维码替换为真实二维码 + 分享鉴权 + 公共分享主页

**解决方案：** 海报中的二维码为占位图标，不可扫码；分享链接无鉴权机制；无公共分享主页页面。

**实现逻辑：**
- **后端**：`collector_privacy` 表新增 `share_token`（哈希存储）、`token_version`、`token_expires_at` 字段
  - POST `/api/collector/share/generate`：生成30天有效期的分享鉴权链接
  - POST `/api/collector/share/reset`：递增版本号使旧 token 立即失效
  - GET `/api/collector/share/profile/{user_id}`：验证 token 后按隐私设置返回不同级别数据（完整/仅统计/私密）
- **前端**：
  - `SharePoster.vue` 使用 `qrcode` 库生成真实二维码，触发生成海报时自动调用分享链接 API
  - 新增 `ShareProfile.vue` 路由页面 `/share/{userId}`，扫码后展示三种场景（完整主页/仅统计/私密）

### 结果
- 海报中显示真实可扫二维码，扫码后按隐私设置展示对应内容
- 分享链接 30 天有效期，可在隐私设置中重置
