# 2026-06-22 更新日志

## 收藏历程功能优化

### 1. 收藏历程时间格式增加秒数展示
**解决方案：** 收藏历程中的交易时间原只展示到日期（yyyy-MM-dd），无法精确区分同一天的多笔交易顺序。

**实现逻辑：**
- `collector_transaction_service.py` 中 `date_str` 格式化字符串从 `%Y-%m-%d` 改为 `%Y-%m-%d %H:%M:%S`
- 所有收藏历程交易记录的时间展示从 `2026-06-22` 变为 `2026-06-22 14:30:25`

### 2. 收藏历程库存数值数据源切换
**解决方案：** 收藏历程时间轴库存数值（balance）原从 order_transactions 按资金流水计算（定金/尾款/补仓记录都会被计入库存变化），与实际库存不一致。现改为时间轴事件仍来自 order_transactions，但库存数值从 asset_transactions 表的 remaining_quantity 获取。

**实现逻辑：**
- 新增 AssetTransaction 查询：按时间正序获取该手办的所有资产交易记录
- 构建时间轴库存快照 `asset_stock_at_date`：遍历 asset_transactions，累计 remaining_quantity（buy 增加，sell 减少）
- 处理每个 order_transaction 事件时，从快照中查找对应时间点的库存值
- 若快照中没有精确匹配的时间点，则取最近的前一个时间点的库存值
- 时间轴事件（交易类型、标签、单价、总金额）仍来自 order_transactions

### 3. 收藏历程 deposit 标签细分
**解决方案：** 当 order_transactions 表的 transaction_type 为 "deposit" 时，不再直接映射为"定金"，而是通过 notes 字段的值进一步区分。

**实现逻辑：**
- `collector_transaction_service.py` 中，将 `transaction_type == 'deposit'` 的单行三元表达式拆分为独立逻辑
- 先检查 notes 字段是否包含"补仓"：若包含，则标签标记为"补仓"；否则才标记为"定金"
- 这样既保留了正常的定金记录标"定金"，也允许补仓操作的 deposit 记录显示为"补仓"

### 4. 收藏历程 balance 标签细分
**解决方案：** 当 order_transactions 表的 transaction_type 为 "balance" 时，不再直接映射为"尾款"，而是通过 notes 字段的值进一步区分。

**实现逻辑：**
- `collector_transaction_service.py` 中，将 `transaction_type == 'balance'` 的单行赋值改为条件判断逻辑
- 先检查 notes 字段是否包含"补仓"：若包含，则标签标记为"补仓"；否则才标记为"尾款"
- 这样补仓操作的 balance 记录也能正确显示为"补仓"而非"尾款"

### 5. 币种变更记录合并（定金/尾款）
**解决方案：** 当定金币种或尾款币种变更时，会产生两条相同时间点的 order_transactions 记录（"币种变更退款"+"币种变更支付"），需要合并为一条变更记录展示。两种类型独立合并，互不干扰。

**实现逻辑：**
- `collector_transaction_service.py` 中引入 `CURRENCY_CHANGE_CONFIG` 配置字典，定义两种类型的关键词和标签映射
  - deposit → "定金币种变更退款" + "定金币种变更支付" → 标签"定金币种"
  - balance → "尾款币种变更退款" + "尾款币种变更支付" → 标签"尾款币种"
- 以 `(date_str, transaction_type)` 作为唯一键，确保同一时间点的定金和尾款变更不会混淆
- 配对成功后，来源金额和币种从退款记录的 `previous_amount` 和 `currency` 字段获取
- 目标金额和币种从支付记录的 `current_amount` 和 `currency` 字段获取
- 生成 type 为 "currency_change" 的合并记录，`CollectionHistory.vue` 通过 `type_label` 区分显示"定金币种"或"尾款币种"

### 6. 币种变更标签颜色区分
**解决方案：** "定金币种"和"尾款币种"的标签和圆点使用同一颜色（紫色），视觉上无法区分，需要分别设置不同颜色以增强辨识度。

**实现逻辑：**

- 定金币种标签维持原有紫色（`#F3E5F5` 背景/`#7B1FA2` 文字）和紫色圆点
- `tagClass` 方法中根据 `type_label === '尾款币种'` 返回对应的样式类
- 同时修复模板中币种变更内容文字：定金币种显示"定金金额"，尾款币种显示"尾款金额"

### 7. 展示分类排除表（软出柜）
**解决方案：** 原有的出柜登记逻辑存在两个问题：(1) 海景房专区的移除操作与展示逻辑不匹配（删标签但展示逻辑不查标签）；(2) 最近入柜、预定中等分类不支持手动移出。现改为统一使用排除表（cabinet_figure_exclusions）实现"软出柜"，不删除藏品也不产生交易流水。

### 19. 修复系统标签统计未按手办去重

### 20. 修改待补款统计逻辑
**解决方案：** "待补款"标签原统计包含 `status IN ('未支付', '已支付')`，即包含定金未支付的订单（连定金都没付，更谈不上补尾款）。逻辑有误，应仅统计"已付定金但尾款未支付"的订单。

**实现逻辑：**
- `collector_tag_service.py` 中"待补款"的查询条件从 `Order.status.in_(['未支付', '已支付'])` 改为 `Order.status == '已支付'`
- 只有已付定金（status='已支付'）但尾款未结清的订单才计入"待补款"
- `get_system_tags` 和 `_get_system_tag_figure_ids` 两处同步更新
- 规则描述同步修正：从"有未付尾款的订单"改为"已付定金但尾款未支付"

  - 支持按日期分组（今天/昨天/前天/日期）、分页查询

  - 抽取 API 调用到 `activityApi.js`
