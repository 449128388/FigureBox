# 2026-06-18 更新日志

## 本命厂商功能实现

### 1. 「本命角色」修改为「本命厂商」
**解决方案：** 将后端收藏柜分类中 role 分类的分组逻辑从按 work（作品）改为按 manufacturer（厂商），名称统一修改为「本命厂商」。

**实现逻辑：**
- 后端 `cabinets.py`：role 分类的分组字段从 `trans.figure.work` 改为 `trans.figure.manufacturer`，卡片名称从「本命角色」改为「本命厂商」
- 前端 `CollectionCabinets.vue` 和 `useCollectorData.js`：入口卡片的 icon 从 💝 改为 🏭，icon_bg 从 `#F0F5E8` 改为 `#E8F4F8`，文案从「0 体 · 暂无数据」改为「暂无本命厂商」
- badge-role 样式从绿色改为青色系（`#E0F7FA` / `#00BCD4`）

### 2. 本命厂商完整 CRUD 功能
**解决方案：** 采用前后端分离架构，后端按企业级服务层模式新增数据模型、服务类、API 端点；前端按组件目录结构新增厂商列表页、详情页、表单弹窗组件及业务逻辑 composable。

**实现逻辑：**

**后端：**
- **数据模型** `favorite_manufacturer.py`：新建 `FavoriteManufacturer` 表，包含 name、name_jp、description、logo_url、website_url、twitter_url、sort_order 字段，支持软删除
- **服务层** `collector_manufacturer_service.py`：封装 `CollectorManufacturerService` 类，提供 `get_all`、`get_by_id`、`create`、`update`、`delete`、`get_count` 静态方法，`_get_figure_stats` 方法通过 `manufacturer` 字段匹配手办统计总藏品、在柜数
- **API** `manufacturers.py`：提供 RESTful 风格接口（`GET /collector/manufacturers` 列表、`POST` 新增、`GET /{id}` 详情含手办列表、`PUT /{id}` 更新、`DELETE /{id}` 删除）
- **路由注册** `collector_router.py`：注册 manufacturers 路由到收集器路由组
- **入口优化** `cabinets.py`：role 分类的 count 优先取已添加的本命厂商数量，meta 显示为「X 家 · 追厂狂魔」

**前端：**
- **组件目录** `ManufacturerList/`：按项目组件拆分规范创建
- **API 层** `manufacturerApi.js`：封装所有后端接口调用
- **业务逻辑** `composables/useManufacturer.js`：使用 Vue composable 模式管理厂商数据状态、弹窗显隐、CRUD 操作
- **厂商列表页** `ManufacturerList.vue`：卡片网格布局，左侧 Logo + 右侧信息（厂商标签、中文名、描述），底部展示总藏品数/在柜数，编辑/删除按钮不穿透点击
- **厂商详情页** `ManufacturerDetail.vue`：Hero 区域展示厂商 Logo、名称、描述、链接，统计面板展示总藏品/在柜/预定中/已出，手办网格展示该厂商下所有藏品
- **表单弹窗** `MakerFormDialog.vue`：表单包含厂商名称（必填）、日文名称、描述、官网链接、推特链接、Logo URL，支持新增/编辑模式切换
- **集成** `Dashboard.vue`：拦截 role 分类点击进入本命厂商独立视图，支持列表→详情→返回的完整交互流程

### 11. 修复本命厂商详情接口获取失败（500/504）
**解决方案：** `GET /api/collector/manufacturers/{id}` 接口响应 504 超时，原因是 `_get_figures_by_manufacturer()` 中将 `Figure.images`（SQLAlchemy Column 描述符对象）作为图片字段返回，FastAPI 无法序列化该对象导致崩溃。

**实现逻辑：**
- `collector_manufacturer_service.py` 中 `_get_figures_by_manufacturer` 方法
- 将 `Figure.images` 改为 `(fig.images[0] if fig.images and len(fig.images) > 0 else "")`，正确取手办实例的第一张图片 URL

### 14. 修复厂商详情中「在柜」和「预定中」统计逻辑
**解决方案：** 厂商详情页的「预定中」统计始终为 0，因为 `_get_figure_stats` 和 `_get_figures_by_manufacturer` 都未实现「预定中」的查询逻辑。

### 20. 厂商详情手办支持多状态标签同时展示

- 筛选逻辑改为检查数组是否包含目标状态

### 24. 收藏历程数据源从 AssetTransaction 改为 OrderTransaction
**解决方案：** 藏品详情中的收藏历程原从 asset_transactions（库存账）获取数据，现改为从 order_transactions（资金账）获取数据，以动态流水形式展示真实资金变动。

**实现逻辑：**
- `collector_transaction_service.py` 重写 `get_figure_transactions` 方法：
  - 查询数据源从 `AssetTransaction` 改为 `OrderTransaction`
  - 交易类型映射：`direction=out + type=buy → 买入`，`direction=in + type=sell → 卖出`，`type=refund → 退款`，`type=fee → 手续费`
  - 库存结余计算：买入增加库存，卖出减少库存，退款/手续费不影响库存
  - 单价使用 `OrderTransaction` 的 `unit_price`（真实交易单价），总金额使用 `total_amount`

### 25. 收藏历程买入交易恢复「补仓」细分标识
**解决方案：** 切换数据源到 OrderTransaction 后，丢失了 asset_transactions 时期通过 notes 字段判断补仓的逻辑，买入统一显示为「买入」。

**实现逻辑：**
- `collector_transaction_service.py` 中 buy 类型判断增加 `t.notes` 检查
- 当 `t.notes` 包含「补仓」关键词时，`label` 标记为 `补仓`，否则标记为 `买入`
- 与前端 `CollectionHistory.vue` 中已有的 `tag-replenish` 样式配合使用

### 26. 收藏历程手续费合并展示及明细格式化
**解决方案：** 同一日期的运费和平台手续费分两条记录展示，需要合并为一条并显示明细。

**实现逻辑：**
- 后端 `collector_transaction_service.py`：
  - 为 fee 交易按 notes 区分 `fee_type`（shipping/platform）
  - 遍历结果时：收集同一日期的连续 fee 记录，合并为一条
  - 合并后增加 `fee_detail` 字段：`{ shipping_fee, platform_fee, total }`
- 前端 `CollectionHistory.vue`：
  - 新增条件渲染：`item.type === 'fee' && item.fee_detail` 时展示合并格式
  - 显示格式：`手续费 · 运费 ¥XX + 平台手续费 ¥XX 合计支出 ¥XXXX`
  - balance 显示条件从 `item.quantity > 0` 改为 `item.balance !== undefined`
  - 新增 `.tag-fee` 蓝色标签样式（#E3F2FD/#1565C0）

### 27. 收藏历程买入交易细分「定金」和「尾款」
**解决方案：** 买入交易统一显示为「买入」，未根据 OrderTransaction 的 `transaction_type` 字段区分定金支付（deposit）和尾款支付（balance）。

**实现逻辑：**
- 后端 `collector_transaction_service.py`：
  - 条件从 `transaction_type == 'buy'` 扩展为 `transaction_type in ('buy', 'deposit', 'balance')`
  - `transaction_type == 'deposit'` → 标签 `定金`
  - `transaction_type == 'balance'` → 标签 `尾款`
  - `transaction_type == 'buy'` → 回退到 notes 判断补仓，否则「买入」
- 前端 `CollectionHistory.vue`：
  - 新增 `tagClass` 方法统一管理标签样式映射
  - 新增 `.tag-deposit`（绿色）和 `.tag-balance`（青色）CSS 样式
