# 2026-06-01 更新日志

## 新增持仓快照功能

### 需求描述
增加持仓快照表，每天记录用户的持仓明细，用于历史收益曲线计算。

### 解决方案
1. 创建 `HoldingSnapshot` 持仓快照模型，记录每个手办每日的持仓明细
2. 创建 `HoldingSnapshotSummary` 汇总记录模型，记录每日持仓汇总数据
3. 创建 `HoldingSnapshotService` 服务类，提供快照生成和查询功能
4. 创建 `HoldingSnapshotScheduler` 定时任务调度器，每天23:30自动执行

### 数据模型
**HoldingSnapshot 持仓快照表：**
- 记录每个用户每天每个手办的持仓明细
- 字段包括：持仓数量、加权平均成本、市场价、市值、浮动盈亏等
- 支持计算持仓天数

**HoldingSnapshotSummary 汇总记录表：**
- 记录每个用户每天的持仓汇总数据
- 字段包括：总市值、总成本、总浮动盈亏、持仓种数、总件数等

### 定时任务
- 每天北京时间23:30自动执行
- 为所有活跃用户生成持仓快照
- 支持手动触发执行

### 结果
- 持仓快照数据自动每日生成
- 支持查询历史日期的持仓状况
- 为历史收益曲线计算提供数据基础

## 修复收益曲线数据逻辑问题

### 问题描述
收益曲线(近1月)当没有持仓快照数据时，不应该生成完整的30天日期序列数据。

### 解决方案
修改 `ProfitCurveService` 服务类中的 `get_profit_curve_data` 方法：
- 仅基于实际持仓快照数据返回收益曲线
- 没有持仓快照数据时，仅返回市值缓存表中实际存在的数据

### 实现逻辑
1. 查询近30天的持仓快照数据
2. 如果有持仓快照数据，直接返回这些数据
3. 如果没有持仓快照数据，查询市值缓存表中实际存在的数据
4. 返回实际存在的数据，不生成或填充缺失日期
5. 如果没有任何数据，返回空列表

### 结果
- 收益曲线仅显示实际存在的持仓快照数据
- 没有快照数据时不生成虚假的历史数据

### 实现逻辑
1. **问题根因**：`getCurrencySymbol` 函数中 CNY 和 JPY 都返回 `¥`，模板中直接拼接符号和数字
2. **修复方案**：新建 `formatCurrency(amount, currency)` 函数，对 JPY 特殊处理返回 `JP¥{formatted}`，其他币种保持 `{symbol}{formatted}` 格式；模板中所有 `{{ getCurrencySymbol(currency) }}{{ formatNumber(amount) }}` 替换为 `{{ formatCurrency(amount, currency) }}`
3. **代码位置**：`BuyOrderDrawer.vue`

### 结果
- 日元金额显示为 `JP¥1000` 而不是 `¥1000`
- 人民币金额保持 `¥100` 不变
- 用户可清晰区分币种
