## 2. 资产看板交易版块-快速操作-撤单功能

### 需求描述
对资产看板-交易版块中的快速操作中的[撤单]按钮进行新增需求，取消未完成的订单，根据已支付金额生成退款流水，若已入库需回滚库存。

### 解决方案
采用前后端分离架构，前端使用两步弹窗设计（选择订单 -> 确认取消），后端采用企业级服务层架构实现撤单业务逻辑。

### 实现逻辑
**后端实现：**
- 创建 `CancelOrderService` 服务类，提供以下核心功能：
  - `get_cancelable_orders`：获取可取消订单列表
    - 过滤条件：订单状态 IN ('未支付', '已支付', '待发货')
    - 返回订单基本信息、已支付金额、是否已入库
  - `get_order_cancel_detail`：获取订单取消详情
    - 判断订单类型（预定单/全款现货/补仓）
    - 计算已支付金额
    - 判断是否已入库
    - 确定退款选项（预定单可选退定金，全款必须退）
  - `cancel_order`：取消订单
    - 验证订单状态（必须为可取消状态）
    - 如果已入库，回滚库存（创建RETURN记录，软删除原买入记录）
    - 如果需要退款，创建退款交易记录
    - 更新订单状态为"已取消"
    - 创建订单状态变更记录
- 在 `trade_records_service/__init__.py` 中导出 `CancelOrderService`
- 在 `trade_records.py` 中添加三个API接口：
  - `GET /cancelable-orders`：获取可取消订单列表
  - `GET /cancelable-orders/{order_id}`：获取订单取消详情
  - `POST /cancel-order/{order_id}`：取消订单

**前端实现：**
- 创建 `CancelOrderListDialog.vue` 组件（Step 1：选择待取消订单）
  - 展示可取消订单列表
  - 显示手办图片、名称、订单类型、已支付金额
  - 已入库订单显示警告提示
  - 点击【取消订单】进入确认弹窗
- 创建 `CancelOrderConfirmDialog.vue` 组件（Step 2：取消确认）
  - 展示订单编号、手办名称、当前状态
  - 支持选择退款选项：
    - 预定单：可选"仅取消保留定金"或"取消并退款"
    - 全款现货/补仓：必须全额退款
  - 支持选择退款方式（原路退回、支付宝、微信等）
  - 已入库订单显示库存回滚警告
  - 高危险操作需二次确认（输入"确认取消"）
  - 确认按钮为红色，强调危险操作
- 创建 `useCancelOrder.js` composable
  - 管理撤单相关的状态和行为
  - 提供两步撤单流程控制
- 更新 `Dashboard.vue`
  - 导入撤单组件和composable
  - 添加撤单成功后的数据刷新逻辑

**与现有模块关联：**
- 交易流水：生成退款流水卡片（收入 +¥XXX），或仅状态变更记录
- 盈亏分析：已取消订单不计入实现盈亏，若之前有卖出关联需重新计算
- 资产看板：库存回滚导致总市值变化，日涨跌可能波动
- 持仓列表：库存扣减，若归零则卡片状态变化

### 结果
- 支持查看可取消订单列表
- 支持预定单选择是否退定金
- 支持全款现货/补仓全额退款
- 支持已入库订单库存回滚
- 高危险操作需二次确认
- 撤单成功后自动更新订单状态
- 自动创建退款流水和库存回滚记录

## 6. 修复新增买入订单抽屉在创建成功后未关闭的缺陷

### 需求描述
修复资产看板-交易-快速操作-买入按钮的点击后的新增买入订单页面在完成订单创建成功后，抽屉弹窗没有关闭的缺陷

### 解决方案
修复 `Dashboard.vue` 中 `v-model` 绑定与子组件 `CreateBuyOrderDrawer` 的 props 名称不匹配的问题

### 实现逻辑
- 问题原因：`Dashboard.vue` 使用 `v-model="createBuyOrderDrawerVisible"`，该语法在 Vue 3 中默认绑定到 `modelValue` prop 和 `update:modelValue` 事件，但 `CreateBuyOrderDrawer` 组件定义的是 `visible` prop 并触发 `update:visible` 事件，导致父子组件间状态不同步
- 修复内容：
  - 将 `v-model="createBuyOrderDrawerVisible"` 改为 `v-model:visible="createBuyOrderDrawerVisible"`，明确指定绑定到 `visible` prop
  - 同时修复 `CreateSellOrderDrawer` 相同的问题
  - 添加 `@success="fetchDashboardData"` 事件监听，确保创建成功后刷新资产看板数据

### 结果
- 新增买入订单创建成功后，抽屉弹窗自动关闭
- 卖出订单抽屉同理修复
- 创建订单后资产看板数据自动刷新

## 7. 修复补仓操作后手办详情中数量未增加的缺陷

### 需求描述
修复资产看板-持仓列表中对"补仓"操作后，手办管理-手办详情中的数量没有增加补仓数量的缺陷

### 解决方案
在订单创建完成后的业务流程中，补充更新手办 `quantity` 字段的逻辑

### 实现逻辑
- 问题原因：创建买入订单（现货/补仓）时，业务代码只创建了库存账记录（`AssetTransaction`）并更新了平均入手价格，但没有同步更新 `figures` 表的 `quantity` 字段，导致手办详情页面显示的数量仍为旧值
- 修复内容：
  - `buy_order_service.py`：在补仓/现货订单创建成功后，增加手办持有数量更新步骤，从库存账（`AssetTransaction`）重新汇总 `remaining_quantity` 并更新到 `figure.quantity`
  - `pay_balance_service.py`：在尾款支付完成、订单标记为"已完成"后，同样增加手办数量更新逻辑
  - `order_crud_service.py`：在手办管理页面创建订单时，同样增加手办数量更新逻辑

### 结果
- 补仓操作后，手办详情中的数量正确增加
- 尾款支付后手办数量同步更新
- 手动创建订单后手办数量同步更新

## 8. 修复卖出操作后手办详情中数量未减少的缺陷

### 需求描述
修复资产看板-持仓列表中对手办进行"卖出"操作后，手办管理-手办详情中的数量没有减少卖出数量的缺陷

### 解决方案
修复 `create_sell_order_from_inventory` API 端点中的逻辑错误：端点曾尝试调用不存在的方法，导致整个请求失败，`SoldOrderCrudService.create_sold_order` 内部已正确处理的所有业务（含手办数量更新）无法正常返回

### 实现逻辑
- 问题原因：
  - `create_sell_order_from_inventory` 端点引用了不存在的方法 `SoldOrderInventoryService.deduct_inventory_on_sell()`，导致 `AttributeError`
  - 同时缺少 `SoldOrderCrudService` 的导入，进一步导致 `NameError`
  - 端点的库存扣减和资金流创建步骤与 `create_sold_order` 内部逻辑重复，属于冗余代码
- 修复内容：
  - 添加 `SoldOrderCrudService` 的导入
  - 移除对不存在方法 `deduct_inventory_on_sell` 的调用
  - 移除冗余的 `create_sell_transaction` 调用（已在 `create_sold_order` 内部自动完成）
  - 移除不再需要的 `SoldOrderInventoryService` 导入
  - `SoldOrderCrudService.create_sold_order` 内部已执行 `SoldOrderFigureService.update_figure_status()`，自动从库存账重新汇总 `remaining_quantity` 并更新到 `figure.quantity`

### 结果
- 卖出操作后，手办详情中的数量正确减少
- 手办零库存时自动标记为售罄（quantity=0）
- 卖出订单创建流程稳定，不再抛出异常
