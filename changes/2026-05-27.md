# 2026-05-27 更新日志

## 实现资产看板日涨跌新需求方案

### 需求背景
资产看板中的"日涨跌"功能需要支持以下场景：
1. 首次使用/无昨日缓存时，诚实告知无对比数据
2. 连续多日未刷新时，向前回溯到最近有缓存的日期作为对比基准
3. 建立每日快照机制，为日涨跌计算提供可靠的数据基础

### 解决方案

#### 1. 建立 user_asset_snapshots 每日快照表
创建 `user_asset_snapshots` 表记录用户每日的资产状况：
- `user_id`: 用户ID
- `snapshot_date`: 快照日期
- `total_asset`: 当日总资产
- `total_cost`: 当日总成本
- `hpi_index`: 当日塑料手办指数（可选）
- `created_at`: 记录时间

#### 2. 创建日涨跌计算服务
创建 `DailyChangeService` 服务类，提供以下功能：
- 计算日涨跌金额和百分比
- 支持向前回溯到最近有缓存的日期
- 首次使用时创建昨日基准数据
- 连续多日未刷新时的历史对比

#### 3. 创建日涨跌定时任务
创建 `DailySnapshotScheduler` 定时任务调度器：
- 每天北京时间 00:05:00 执行
- 自动为所有用户创建资产快照
- 使用 APScheduler 实现单机 Cron 调度
- 统一使用 UTC+8（北京时间）

#### 4. 修改资产看板API
- 使用新的日涨跌服务计算涨跌数据
- 返回 `comparison_date` 和 `is_historical_comparison` 字段
- 新增 `/dashboard/init-daily-change` 接口用于首次初始化

#### 5. 前端实现日涨跌展示组件
创建 `DailyChangeDisplay` 组件：
- 无数据时显示 "-- (--%)"，悬停提示引导用户初始化
- 正常日涨跌显示涨跌金额和百分比
- 历史对比时显示 "较X月X日 +¥X,XXX (+X.XX%)"
- 根据涨跌情况显示不同颜色（涨红跌绿）

### 实现逻辑

| 场景 | 前端展示 | 后端逻辑 |
|------|---------|---------|
| 首次使用/无昨日缓存 | `日涨跌: -- (--%)`，悬停提示 | 查找昨日快照，不存在则标记 `has_daily_change=false` |
| 连续多日未刷新 | `较5月20日 +¥1,200 (+12%)` | 向前回溯到最近有缓存的日期作为对比基准 |
| 正常日涨跌 | `+¥1,200 (+12%)` 或 `-¥500 (-5%)` | 使用昨日快照计算涨跌 |

### 涉及文件
- `backend/app/models/user_asset_snapshot.py`: 用户资产快照模型
- `backend/app/services/dashboard_service/assets_service/daily_change_service.py`: 日涨跌计算服务
- `backend/app/services/scheduler_service/daily_snapshot_scheduler.py`: 日涨跌定时任务
- `backend/app/api/assets/dashboard_asset.py`: 资产看板API
- `frontend/src/views/Dashboard/components/reseller/assets/DailyChangeDisplay.vue`: 日涨跌展示组件
- `frontend/src/views/Dashboard/components/reseller/assets/AssetOverview.vue`: 资产概览组件

### 结果
- 日涨跌计算更加准确可靠
- 支持多种数据缺失场景的智能处理
- 用户首次使用时明确告知无对比数据
- 连续多日未刷新时自动回溯到最近有效日期

## 修复刷新资产按钮未创建日涨跌基准数据问题

### 问题描述
点击【刷新资产】按钮后，`user_asset_snapshots` 表没有数据，导致日涨跌功能无法正常工作。

### 问题原因
前端点击【刷新资产】按钮时，只调用了获取资产数据的 API，没有调用初始化日涨跌基准数据的 API。根据需求，当用户首次点击【刷新资产】且 `has_daily_change = false` 时，应该自动将当前总资产写入 `user_asset_snapshots` 表作为基准日数据。

### 解决方案
修改 `refreshData` 函数，在刷新资产数据后，检查 `has_daily_change` 字段：
- 如果为 `false`，自动调用 `/assets/dashboard/init-daily-change` 接口创建基准数据
- 创建成功后显示提示信息，并重新获取数据更新显示

### 实现逻辑
1. 用户点击【刷新资产】按钮
2. 调用 `fetchDashboardData()` 获取资产数据
3. 检查 `dashboardData.summary.has_daily_change`
4. 如果为 `false`，自动调用 `init-daily-change` 接口
5. 创建成功后提示用户"日涨跌基准数据已创建，明天开始正常计算"
6. 重新获取数据更新前端显示

### 涉及文件
- `frontend/src/views/Dashboard.vue`: 修改 `refreshData` 函数，增加自动初始化日涨跌基准数据逻辑

### 结果
- 点击【刷新资产】按钮时，如果日涨跌数据不存在，自动创建基准数据
- `user_asset_snapshots` 表正常写入数据
- 用户明天即可正常查看日涨跌

   - `daily_snapshot_scheduler` - 日涨跌快照定时任务（00:05执行）

2. 创建 `SchedulerManager` 类统一启动/停止所有定时任务

3. 保持 `start_scheduler()` 和 `stop_scheduler()` 接口不变，确保兼容性

### 涉及文件
- `backend/app/services/scheduler_service/__init__.py`: 修复定时任务导入和启动逻辑

## 优化日涨跌展示逻辑 - 支持四级优先级对比

### 需求背景
日涨跌功能需要更精细的对比逻辑，按照优先级依次查找对比基准：
1. 昨天（T-1）- 正常情况
2. 前天（T-2）- 昨天漏拍/未刷新行情
3. 最近有数据的日期 - 连续多日未打开系统（超过30天加提示）
4. 无历史数据 - 全新用户

### 解决方案

#### 后端修改
修改 `DailyChangeService.calculate_daily_change()` 方法，实现四级优先级查找：

| 优先级 | 对比基准 | 前端展示 | 适用场景 |
|:---:|:---|:---|:---|
| 1 | 昨天（T-1） | `较昨日 +¥X (+Y%)` | 正常情况，最理想 |
| 2 | 前天（T-2） | `较5月26日 +¥X (+Y%)` | 昨天漏拍/未刷新行情 |
| 3 | 最近有数据的日期 | `较5月20日 +¥X (+Y%)` | 连续多日未打开系统 |
| 3+ | 超过30天前 | 加 Tooltip 提示 | "已30天未更新行情" |
| 4 | 无历史数据 | `-- (--%)` | 全新用户，首次使用 |

新增返回字段：
- `comparison_type`: 对比类型（yesterday/day_before_yesterday/recent/stale）
- `days_since_last_update`: 距离上次更新的天数
- `show_stale_warning`: 是否显示过期警告（超过30天）

#### 前端修改
修改 `DailyChangeDisplay` 组件：
- 根据 `comparison_type` 智能显示对比日期（昨天显示"昨日"，其他显示具体日期）
- 超过30天未更新时显示虚线警告样式和 Tooltip 提示
- 支持新的 props 传递

### 涉及文件
- `backend/app/services/dashboard_service/assets_service/daily_change_service.py`: 实现四级优先级查找逻辑
- `backend/app/api/assets/dashboard_asset.py`: 返回新的日涨跌数据字段
- `frontend/src/views/Dashboard/components/reseller/assets/DailyChangeDisplay.vue`: 优化展示逻辑
- `frontend/src/views/Dashboard/components/reseller/assets/AssetOverview.vue`: 传递新的 props

### 结果
- 日涨跌对比更加智能，优先使用最近的数据
- 超过30天未更新时给用户明确提示
- 支持"今日实时市值 vs 最近有效历史日期"的对比

## 修复买入订单数据取值错误

### 问题描述
交易流水（按时间倒序）中买入订单（聚合卡片）的数据取值错误，之前从 `OrderTransaction` 表获取数据，但应该从 `orders` 表获取买入订单数据。

### 问题原因
`_get_aggregated_buy_records` 方法错误地从 `OrderTransaction` 表查询买入交易记录：
- `OrderTransaction` 表存储的是资金流水记录
- `orders` 表存储的是实际的买入订单信息（包含定金、尾款、店铺等）
- 买入订单卡片应该展示 `orders` 表的订单信息

### 解决方案
修改 `_get_aggregated_buy_records` 方法：

#### 1. 修改数据来源
- 从 `orders` 表查询买入订单（`Order` 模型）
- 关联 `figures` 表获取手办名称
- 关联 `OrderTransaction` 表获取该订单的费用明细

#### 2. 计算逻辑调整
- 总支出金额 = 定金（deposit）+ 尾款（balance）
- 订单时间使用 `created_at` 字段
- 平台信息使用 `shop_name` 字段
- 订单状态映射：已完成→✅ 成功，已支付→⏳ 进行中，未支付→⏳ 未支付，已取消→❌ 已取消

#### 3. 费用明细查询
- 从 `OrderTransaction` 表查询该订单关联的费用记录（transaction_type = "fee"）
- 按时间正序排列

### 涉及文件
- `backend/app/services/dashboard_service/trade_records_service/transaction_query_service.py`: 修改 `_get_aggregated_buy_records` 方法，改为从 `orders` 表获取数据

### 结果
- 买入订单卡片正确展示 `orders` 表的订单数据
- 支出金额正确计算（定金 + 尾款）
- 平台信息正确显示店铺名称
- 订单状态根据实际状态映射显示

## 修复买入订单抽屉 401 认证错误

### 问题描述
调用 `/api/trade_records/buy-order/1` 接口返回 401 Unauthorized 错误。

### 根因分析
通过查看后端日志发现：
- 其他接口请求（如 `/api/trade_records/dashboard`）携带了 `Authorization: Bearer ...` header

### 解决方案
修改 `BuyOrderDrawer.vue` 中的 axios 导入：
- 修改前：`import axios from 'axios'`
- 修改后：`import axios from '../../../../../axios'`

### 涉及文件
- `frontend/src/views/Dashboard/components/reseller/trade/BuyOrderDrawer.vue`: 修改 axios 导入路径

### 结果
- 买入订单抽屉组件的请求正确携带认证 token
- `/api/trade_records/buy-order/{order_id}` 接口可正常访问
