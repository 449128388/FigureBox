   - 调用后端API创建卖出订单

   - 将持仓列表的"卖出"操作改为打开快速卖出弹窗

## 修复库存账卖出记录价格错误

### 问题描述
当手办发生售卖时，`asset_transactions` 表中的卖出记录（transaction_type='sell'）错误地记录了销售价（sell_price），而应该记录进货价（成本价）。这导致库存账无法正确计算剩余持仓的成本。

### 解决方案
修改 `SoldOrderInventoryService.deduct_inventory` 方法：
1. 将卖出记录的 `price` 字段从 `sold_order.sell_price` 改为 `sold_order.cost_price`
2. 将 `total_amount` 计算从销售价改为成本价
3. 更新备注信息，明确标注为"进货成本价"

### 实现逻辑
- **库存账的 price 字段**：用于记录成本基准，买入时记录买入价，卖出时也应记录对应的成本价
- **成本价来源**：从 `SoldOrder.cost_price` 获取，这是创建订单时传入的成本单价
- **数据一致性**：修复后，库存账可以正确计算剩余持仓的实际成本

### 问题描述

### 解决方案
修改 `holding_position_service.py` 中的两个方法：

## 修复快速卖出后库存未变化及price数据错误

### 问题描述
1. 在资产看板-持仓列表中进行卖出后，持仓列表的库存没有发生变化
2. 卖出后 `asset_transactions` 表中的 `price` 字段填入数据错误（填入了总价而非单价）

### 问题分析
1. **库存未变化**：`deduct_inventory` 方法中 `quantity_to_sell` 被硬编码为 1，而不是从订单中获取实际卖出数量
2. **price 数据错误**：`unit_cost_price = cost_total` 直接使用了总价作为单价，没有除以数量

### 解决方案
1. **添加 quantity 字段到 SoldOrder 模型**：
   - 在 `sold_order.py` 模型中添加 `quantity` 字段记录卖出数量
   - 在 `SoldOrderBase` schema 中添加 `quantity` 字段，默认值为 1

2. **修改库存扣减逻辑**：
   - 从 `sold_order.quantity` 获取实际卖出数量
   - 使用 `cost_total / quantity_to_sell` 计算单位成本价（进货价）

3. **修改快速卖出服务**：
   - 在创建订单时传入 `quantity` 参数

4. **修改订单创建服务**：
   - 在创建 `SoldOrder` 记录时保存 `quantity` 字段

### 实现逻辑
- **数量传递链路**：快速卖出 → QuickSellService → SoldOrderCreate → SoldOrderCrudService → SoldOrder (保存 quantity)
- **库存扣减**：deduct_inventory 从 sold_order.quantity 获取数量，扣减对应数量的买入记录 remaining_quantity
- **单价计算**：price = cost_price / quantity（记录进货单价，用于后续成本计算）
- **数据一致性**：卖出数量、库存扣减数量、交易记录数量保持一致
