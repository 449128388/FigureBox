# 2025-05-08 更新日志

## 补仓功能订单数量修复

### 问题背景
在资产看板-持仓列表模块进行补仓操作时，如果补仓数量为N体，系统只创建了1条订单记录，而正确的逻辑应该是创建N条订单记录（每体手办对应一条订单）。

### 解决方案
1. 修改补仓服务，根据补仓数量循环创建多个订单，每个订单对应1体手办
2. 每条订单定金为单价，而非总价
3. 更新返回结果为订单ID列表
4. 资产交易记录和订单交易记录关联第一个订单ID

### 实现效果
- ✅ 补仓N体手办时，正确创建N条订单记录
- ✅ 每条订单独立显示，便于管理和追踪
- ✅ 成本计算逻辑保持正确

## 资产看板总资产和仓位统计逻辑修复

### 问题背景
资产看板-资产模块中的总资产和仓位统计不正确，需要按照新的统计规则进行修复。

### 解决方案

**1. 总资产统计规则修复：**
- 统计尾款管理列表中状态为"已完成"的全部订单的手办市场总价
- 计算公式：Σ(手办市场价)  // 每个已完成订单对应的手办市场价
- 修改 `TotalAssetsCalculator` 类，新增 `calculate_by_orders` 方法
- 在 `assets.py` API 接口中使用新方法计算总资产

**2. 仓位统计已投入成本修复：**
- 统计尾款管理中所有订单的尾款+定金的总和
- 考虑定金和尾款的币种，按照汇率转换为人民币进行结算
- 汇率配置：
  - CNY: 1.0（人民币）
  - JPY: 1/23（日元）
  - USD: 7.0（美元）
  - EUR: 8.0（欧元）
- 计算公式：已投入成本 = Σ(定金 × 汇率 + 尾款 × 汇率)
- 修改 `PositionCalculator` 类，新增 `_convert_to_rmb` 和 `_calculate_invested_cost_by_orders` 方法
- 新增 `calculate_by_orders` 方法支持基于订单的仓位计算
- 在 `assets.py` API 接口中使用新方法计算仓位

### 实现效果
- ✅ 总资产只统计已完成订单的手办市场总价
- ✅ 仓位已投入成本基于所有订单的定金+尾款计算
- ✅ 支持多币种汇率转换，统一以人民币结算
- ✅ 统计逻辑与业务需求保持一致

### 部署更新

- 执行 `docker-compose up -d --build` 重新部署服务
