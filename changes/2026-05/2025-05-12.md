# 2025-05-12 更新日志

## 已出售订单模块 - 盈亏预览多币种结算

### 需求背景
已出售订单的价格成本字段支持多币种选择（CNY/USD/JPY/EUR），但盈亏预览需要统一以人民币结算，方便用户了解实际收益情况。

### 解决方案

#### 后端实现

**1. 新增币种转换服务 `CurrencyService`**
- 创建 `app/services/currency_service.py` 独立服务模块
- 汇率配置（相对人民币）：
  - CNY: 1.0
  - USD: 7.0 (1美元 = 7人民币)
  - EUR: 8.0 (1欧元 = 8人民币)
  - JPY: 1/23 (1人民币 = 23日元)
- 提供核心方法：
  - `to_cny()`: 任意币种转人民币
  - `calculate_profit_in_cny()`: 多币种订单盈亏统一计算

**2. 更新 `SoldOrderCrudService`**
- 引入 `CurrencyService` 依赖
- 新增 `_calculate_profit_with_currency()` 方法，支持多币种自动转换
- 创建/更新订单时，自动将所有币种金额转换为人民币后计算净利润和利润率
- 更新逻辑同时监听币种字段变化，币种切换时自动重新计算

#### 前端实现

**1. 重构 `ProfitTab.vue` 盈亏预览组件**
- 新增汇率转换逻辑，与后端汇率配置保持一致
- 界面展示优化：
  - 顶部添加转换说明提示
  - 原始金额区域：显示各字段原始币种金额
  - 人民币结算区域：展示转换后的计算过程
  - 汇率参考区域：显示当前使用的汇率
  - 盈亏状态指示器：直观展示盈亏状态
- 当字段币种非人民币时，显示转换后的人民币金额（≈ ¥xxx）

### 业务逻辑

**盈亏计算公式（统一人民币结算）：**
```
净利润 = 卖出价(CNY) - 成本价(CNY) - 运费(CNY) - 手续费(CNY)
利润率 = (净利润 / 成本价(CNY)) × 100%
```

**汇率转换逻辑：**
- 所有金额字段在计算盈亏前，先根据各自币种转换为人民币
- 转换后的盈亏金额和利润率存储到数据库
- 前端预览实时计算，后端保存时再次计算确保一致性

## 已出售订单模块 - 多模块联动集成

### 需求背景
已出售订单需要与系统中其他模块进行数据联动，确保库存、资金、资产等数据的一致性。

### 解决方案

#### 后端实现

**1. 新增已出售订单交易服务 `SoldOrderTransactionService`**
- 创建 `app/services/sold_order_service/sold_order_transaction_service.py`
- 功能：在尾款管理（OrderTransaction）中创建卖出订单主记录
- 创建3笔资金流水：
  - 收入（卖出价）- sell 类型
  - 支出（运费）- fee 类型
  - 支出（手续费）- fee 类型

**2. 新增已出售订单库存服务 `SoldOrderInventoryService`**
- 创建 `app/services/sold_order_service/sold_order_inventory_service.py`
- 功能：库存账扣减（AssetTransaction）
- 创建卖出交易记录，扣减买入记录的 remaining_quantity
- 支持库存恢复（订单删除时）

**3. 新增已出售订单手办服务 `SoldOrderFigureService`**
- 创建 `app/services/sold_order_service/sold_order_figure_service.py`
- 功能：更新手办聚合状态
- 更新当前库存数量、售罄状态

**4. 更新 `SoldOrderCrudService`**
- 集成上述服务，实现创建订单时的多模块联动：
  1. 创建已出售订单记录
  2. 尾款管理：创建卖出订单主记录
  3. 资金账：创建3笔资金流水
  4. 库存账：扣减库存数量
  5. 资产看板：盈亏分析数据（通过净利润字段）
  6. 手办聚合状态：更新库存数量
- 删除订单时联动恢复库存和手办状态
- 所有操作在事务中执行，确保数据一致性

### 业务逻辑

**创建订单时的联动流程：**
```
创建已出售订单
  ↓
创建尾款管理卖出记录（sell类型）
  ↓
创建资金流水（收入+支出）
  ↓
扣减库存（AssetTransaction sell类型）
  ↓
更新手办库存数量
  ↓
提交事务
```

**删除订单时的联动流程：**
```
软删除已出售订单
  ↓
恢复库存数量
  ↓
恢复手办聚合状态
  ↓
提交事务
```

## 资产看板 - 持仓列表库存统计逻辑修正

### 问题背景
已出售订单创建时会扣减库存（创建 AssetTransaction sell 记录），但资产看板的持仓列表统计是基于订单表（Order）而非库存账（AssetTransaction），导致已出售订单不会直接影响持仓列表的库存数量，造成数据失真。

### 解决方案

#### 后端实现

**1. 更新 `HoldingPositionService`**
- 新增 `get_figure_inventory_from_asset_transactions()` 方法
- 从库存账（AssetTransaction）获取真实库存数量
- 统计逻辑：查询买入记录（transaction_type='buy'）的 remaining_quantity 总和
- 已出售订单会创建 sell 记录并扣减买入记录的 remaining_quantity

**2. 更新 `HoldingAnalysisService`**
- 修改 `build_holding_detail()` 和 `build_all_holdings()` 方法签名
- 传入数据库会话和用户ID，用于查询真实库存
- 修改 `analyze_all_distributions()` 方法，使用新的库存统计方式

**3. 更新 `assets.py` API**
- 移除基于订单数量的库存统计逻辑
- 调用服务层时传入数据库会话和用户ID

### 业务逻辑

**修改后的库存统计流程：**
```
资产看板请求持仓列表
  ↓
查询 AssetTransaction 买入记录
  ↓
累加 remaining_quantity（已扣除卖出部分）
  ↓
返回真实库存数量
```

**数据一致性保障：**
- 已出售订单创建时：创建 sell 记录，扣减对应 buy 记录的 remaining_quantity
- 已出售订单删除时：恢复 buy 记录的 remaining_quantity
- 资产看板始终从 AssetTransaction 获取最新库存

## 已出售订单模块 - shipping_date字段类型修复

### 问题背景
创建已出售订单时，接口返回 422 错误："Datetimes provided to dates should have zero time - e.g. be exact dates"

### 原因分析
- `shipping_date` 字段在 Schema 中定义为 `date` 类型
- 前端传入的是 ISO 8601 格式的日期时间字符串（如 `"2026-05-19T16:00:00.000Z"`）
- Pydantic 的 `date` 类型要求时间部分为零（纯日期），但传入的数据包含时间部分

### 解决方案

#### 后端实现

**更新 `SoldOrderBase` 和 `SoldOrderUpdate` Schema**
- 将 `shipping_date` 字段类型从 `date` 改为 `datetime`
- 支持接收带时间部分的日期时间字符串

#### 后端实现
- 将 `func.case(...)` 替换为 `case(...)`
- 添加 `case` 导入：`from sqlalchemy import func, case`
