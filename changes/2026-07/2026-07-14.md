# 2026-07-14 更新日志

### 1. 实现 MinIO 图床设置功能（用户自定义配置生效）

**解决方案：** 用户可以在"个人中心 → MinIO 图床设置"中填写自定义 MinIO 配置（服务器地址、Access Key、Secret Key、Bucket、图片访问域名等），保存后上传图片时系统将自动使用用户的 MinIO 配置进行上传，而非始终使用系统环境变量中的默认 MinIO。

**实现逻辑：**

- **后端 `storage_service.py`**：
  - 新增 `_get_client_for_config()` 方法：根据用户自定义配置字典创建独立的 MinIO 客户端实例。
  - 新增 `_ensure_bucket_for_client()` 方法：为用户自定义的 MinIO 客户端确保 bucket 存在并设置公开读策略。
  - 新增 `_extract_user_config()` 方法：从用户对象（`User`）中提取 MinIO 配置字段，若用户未配置 endpoint 则返回 `None`，触发系统默认兜底。
  - 重构 `upload_image()`：新增 `minio_config` 可选参数，当传入有效配置时，上传流程切换到用户自定义 MinIO（创建客户端 → 确保 bucket → 上传文件 → 使用配置中的 public_url 构造返回 URL）；未传入时保持原有系统环境变量流程。
  - 重构 `delete_image()` 和 `is_minio_url()`：同步新增 `minio_config` 参数，确保用户自定义 MinIO 中的图片也能正确删除和识别。
- **后端 `upload.py`**：单图和多图上传接口提取 `current_user` 的 MinIO 配置后透传给 `StorageService.upload_image()`。

### 2. 删除 MinIO 配置中无用的 region 字段

**解决方案：** `region` 字段在 MinIO 单节点部署下没有任何实际作用（MinIO 服务端忽略 region 参数，与 AWS S3 不同），`us-east-1` 适用于所有环境，该字段只会给用户带来困惑。

**实现逻辑：**

- **后端 `models/user.py`**：删除 `minio_region` 字段定义及其 `__init__` 默认值。
- **后端 `schemas/user.py`**：从 `MinIOConfigUpdate` 中删除 `region` 字段。
- **后端 `services/storage_service.py`**：删除 `_get_client_for_config()` 和 `_extract_user_config()` 中的 region 相关代码。
- **后端 `services/minio_config_service.py`**：删除 `get_minio_config()`、`update_minio_config()` field_mapping 和 `test_connection()` 中的 region 代码。
- **`docker-compose.yml` / `docker-compose-nas.yml`**：删除 `MINIO_REGION` 环境变量配置。
- **前端 `Profile.vue`**：删除 region 输入框 UI、数据模型和保存/加载逻辑。
- **`entrypoint.sh`**：新增启动时自动清理 `users_info` 表中残留的 `minio_region` 字段的脚本。

### 3. MinIO 图床设置新增"恢复默认"按钮

**解决方案：** 用户在 MinIO 图床设置中修改配置后，可通过"恢复默认"按钮一键将配置回退到系统环境变量定义的出厂默认值（非清空字段），避免手动逐个删除。

**实现逻辑：**

- **后端 `minio_config_service.py`**：新增 `_get_env_defaults()` 工具函数读取环境变量默认值；新增 `reset_minio_config()` 方法将用户的 `minio_*` 字段重置为环境变量默认值后提交。
- **后端 `minio_config.py`**：新增 `POST /api/minio/reset` 端点。
- **前端 `Profile.vue`**：在"保存配置"按钮右侧新增"恢复默认"按钮，点击后调用重置 API 并将返回的默认配置刷新到表单。

### 4. 修复愿望清单 purchased 状态缺少"转入手办库"按钮

**解决方案：** 愿望清单卡片中"转入手办库"按钮的显示条件为 `item.status !== 'purchased' && item.status !== 'cancelled'`，当状态为 `purchased`（已购买）时按钮被隐藏，用户无法将已购买的手办转入手办库。

**实现逻辑：**

- **前端 `WishlistCard.vue`**：将按钮显示条件由 `!== 'purchased' && !== 'cancelled'` 改为仅 `!== 'cancelled'`，已购买状态也可显示"转入手办库"按钮。

### 5. 手办库编辑表单规格侧边栏新增备注输入框

**解决方案：** 手办编辑表单的规格侧边栏中缺少备注字段，且 API 响应模型因直接使用 SQLAlchemy 模型可能导致 Pydantic v2 序列化时遗漏 `note` 字段。

**实现逻辑：**

- **后端 `schemas/figure.py`**：`FigureUpdate` 模型新增 `note` 字段；`FigureListItem` 新增 `note` 字段；新建 `FigureDetailResponse` 模型（继承 `FigureListItem`，补充 `images`、`source_url`、`wishlist_status` 等完整字段）。
- **后端 `api/figures.py`**：详情/创建/更新接口的 `response_model` 从 SQLAlchemy `Figure` 模型改为 `FigureDetailResponse` Pydantic 模型，确保 `note` 等字段在响应中正确序列化；同时修正 `created_at`/`updated_at` 字段类型为 `datetime` 避免响应验证失败；增加 `response_model_exclude={'image'}` 消除详情接口中冗余的 `image` 字段。
- **前端 `useFigureManagement.js`**：`defaultFigure` 新增 `note: ''` 默认值。
- **前端 `FormSpecsTab.vue`**：规格标签页 2 列网格下方新增全宽备注文本域（`el-input type="textarea"`），绑定 `localFigure.note`，并添加 `.full-width` 样式使其跨列。

### 6. 修复手办列表接口 note 字段返回 null 的缺陷

**解决方案：** `GET /api/figures/` 接口在构造 `FigureListItem` 响应对象时遗漏了 `note` 字段，导致接口始终返回 `note: null`，即使 `figures` 表中存有备注数据也无法展示给前端。

**实现逻辑：**

- **后端 `figure_query_service.py`**：在 `get_figures_list` 和 `get_figures_with_stock` 两个方法中，构造 `FigureListItem` 时显式传入 `note=figure.note`，与 Pydantic Schema 中的 `note` 字段对应。

### 7. 修复 URL 智能抓取保存愿望清单时厂商字段错位的缺陷

**解决方案：** HPOI 解析器将页面的"发行"（publisher）保存到 `parsed_data.manufacturer`、"制作"（producer）保存到 `parsed_data.production`，保存到愿望清单时应以"制作"作为厂商归属到 `figures.manufacturer` 字段。

**实现逻辑：**

- **前端 `useWishlistUrlFetch.js`**：保存到愿望清单时，将 `manufacturer` 字段的取值改为 `result.value.production || result.value.manufacturer`，优先使用"制作"数据，无值时降级到"发行"数据。

### 8. 修复愿望清单编辑弹窗中厂商和比例下拉选项为固定写死值的缺陷

**解决方案：** 愿望清单手动录入/编辑弹窗中，厂商（manufacturer）和比例（scale）下拉选项为前端硬编码的固定值，且后端接口仅查询愿望清单数据，用户在录入或编辑时无法选择手办库中已存在的厂商或比例。

**实现逻辑：**

- **后端 `wishlist_query_service.py`**：新增 `get_scales()` 静态方法；`get_manufacturers()` 和 `get_scales()` 查询范围从仅愿望清单改为所有活跃手办，获取全部手办去重后的 `manufacturer` 和 `scale` 值。
- **后端 `wishlist.py`**：新增 `GET /wishlist/scales` API 端点。
- **前端 `wishlistApi.js`**：新增 `scales()` 方法调用 `/wishlist/scales` 接口。
- **前端 `WishlistManualModal.vue`**：厂商和比例下拉选项改为从数据库动态获取去重后的数据，删除硬编码的固定选项。

### 9. 修复手办编辑弹窗在图片上传过多时取消和保存按钮被截断的缺陷

**解决方案：** 手办编辑弹窗容器设置了 `overflow: hidden`，当图片上传过多导致内容高度超出 `max-height: 90vh` 时，底部的取消/保存按钮被裁剪不可见。

**实现逻辑：**

- **前端 `FigureForm.vue`**：将 `.form-container` 的 `overflow: hidden` 改为 `overflow-y: auto`，当图片上传区域内容过多时容器自动出现垂直滚动条，确保底部操作按钮始终可访问。

### 10. 隐藏手办编辑弹窗内部滚动条

**解决方案：** 上一次修复后，弹窗在图片过多时虽然可以滚动，但显示的滚动条影响了弹窗美观。

**实现逻辑：**

- **前端 `FigureForm.vue`**：使用 CSS 隐藏 `.form-container` 的滚动条（`scrollbar-width: none`、`-ms-overflow-style: none`、`::-webkit-scrollbar { display: none }`），保留滚动能力的同时视觉上不显示滚动条。
