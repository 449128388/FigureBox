### 1. 修复 CSS line-clamp 属性被 linter 标记警告

**解决方案：** `-webkit-line-clamp` 是 WebKit 前缀的非标准属性，部分 CSS linter（如 stylelint）会将其标记为警告。现代 CSS 已定义标准 `line-clamp` 属性，同时保留二者可消除警告且保持兼容。

**实现逻辑：**

- **前端 `WishlistCard.vue`**：`.card-title-link` 和 `.card-note` 的 `-webkit-line-clamp: 2` 后追加标准 `line-clamp: 2`，前缀属性用于旧版 WebKit，标准属性用于现代浏览器，linter 不再警告。

### 15. 导入手办时补充 activity_feed 动态流事件记录

**解决方案：** 手办管理导入手办时通过 `FigureImportService.import_orders()` 和 `import_sold_orders()` 创建买入/卖出订单，但全程未调用 `CollectorActivityService` 写入 `activity_feed` 表，导致收藏家模式的动态流页面缺失导入的数据。需在导入流程末尾追加与 CRUD（order_crud_service / sold_order_crud_service）一致的事件写入。

### 17. 修复 asset_value_cache 缓存被动生成缺陷

**排查结论：** `asset_value_cache` 表的 `created_at` 字段记录的都是用户访问 `/dashboard` 路由的时间（如 09:38、09:25、11:05 等），证明数据是被动生成的——只有用户访问看板时 `DailyCacheService.save()` 才被隐式调用。调度器虽然配置了"每天 23:30"执行，但实际从未生效。这导致：① 未访问看板的用户当日无缓存；② 日涨跌计算依赖"昨日缓存"，因缺失而出错；③ 截图 7-04、7-05 无数据即是用户两天未访问。

**解决方案：** 将"被动写入"改为"调度器主动写入 + 00:10 兜底补齐"，确保每日 23:59 准时落地当日真实持仓市值，无需依赖任何用户访问。

**实现逻辑：**

- **后端 `app/services/scheduler_service/asset_cache_scheduler.py`**：① 修复 `start()` 中 `if not self._scheduler:` 错误（原代码永远会重复创建新调度器）；② 调度时间由 23:30 改为 23:59（更接近收盘时刻）；③ 新增 00:10 兜底任务，检查并补齐昨日缺失缓存（防止 23:59 容器重启等异常）；④ 拆出通用 `_save_user_cache_for_date(date)` 方法供两套任务复用。
