## 缺陷修复 → 3. HPI 走势曲线因 hpi_daily 缺失日期导致断点

**解决方案：** HPI 每日 00:30 跑批依赖系统持续运行；服务器关机/调度异常会导致 hpi_daily 出现 1-N 天缺失，前端 HPI 走势图（ECharts 折线）按 record_date 升序渲染时表现为「水平断点+垂直跳变」。本次在 `HPIService.run_daily_batch` 跑批流程前插入「缺失快照补全」步骤：以「最近一次有效快照日期 + 1」为起点，扫描到「target_date - 1」，对每个缺失日期，沿用最近一次有效快照的 index_value / avg_return / total_figures / holding_figures / sold_figures / up_count / flat_count / down_count / sold_up_count / sold_down_count / in_cabinet_value / sold_value 与完整 hpi_components 成分股数据，写入 hpi_daily 与 hpi_components，使 HPI 走势曲线在缺失区间呈现为「沿上一交易日水平的连续段」，而非断点。

**实现逻辑：**

- **新增方法** `HPIService._backfill_missing_snapshots(db, user_id, target_date) -> int`：
  - 查询该用户最近一次有效快照（`record_date` 倒序）
  - 无快照：返回 0，由主流程首次正常生成今日快照
  - 最近快照日期 ≥ 今日：返回 0，无缺失
  - 计算缺失区间 `[latest_date + 1, target_date - 1]`
  - 预取最近一次的 hpi_components 全量数据，作为「上一有效交易日成分股快照」
  - 用一次 `SELECT record_date` 查出区间内已存在的日期集合，对未在集合中的每个日期插入新行（hpi_daily + 配套 hpi_components）
  - 区间内缺失日期连续补全（不留空洞），commit 一次性写入
  - 返回实际补全天数，调用方据此打日志
- **接入点** `HPIService.run_daily_batch`：在 `_calculate_and_save(db, user_id, today)` 之前调用一次 `_backfill_missing_snapshots`，保证「今日 HPI 真实计算」之前缺失区间已用「上一有效交易日指数」补齐
- **幂等性**：通过「区间内已存在日期集合」过滤 + `UniqueConstraint("user_id", "record_date")` 兜底，多次启动 / 启动后立即首次跑批 / 手动重跑均不会重复插入
- **事务**：补全过程单独 commit（写入缺失区间）；后续主流程（_calculate_and_save）按自己的事务处理今日数据；任一环节失败回滚不影响其他用户
- **不影响**：首次跑批（无历史快照时）由主流程正常生成今日指数，无补全动作
- **前端零改动**：ECharts 按 record_date 升序连点即可，补全的「连续段」自然呈现为水平线

## 缺陷修复 → 24. `useBackup.js` 触发 IDE ts(1149) 「文件名仅大小写不同」报错

- **影响范围**：新增 `frontend/jsconfig.json` 一个文件，**不影响构建产物**（Vite 用 esbuild 走自己的模块解析，不读 jsconfig.json）
