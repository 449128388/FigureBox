### 1. 修复超时登出设置未生效问题

**解决方案：** 之前的超时登出设置仅保存到数据库，但 JWT Token 的过期时间始终使用硬编码的 60 分钟，用户的超时设置完全未生效。修改后，Token 的过期时间与用户的超时登出设置保持一致。

**实现逻辑：**
- **jwt.py**：`create_access_token` 新增 `expires_delta` 参数，支持自定义 Token 过期时间
- **auth.py**：登录和注册时读取用户的 `session_timeout_minutes` 设置，传递给 `create_access_token`（0 表示永不超时 ≈ 365天）
- **base.py**：`get_current_user` Token 续期时使用用户的超时设置
- **main.py**：`TokenRefreshMiddleware` 中间件续期时从数据库查询当前用户，使用其超时设置

**验证结果：**
- 默认超时（30分钟）：Token 30 分钟后过期 ✅
- 自定义超时（5分钟）：Token 5 分钟后过期 ✅
- 永不超时（0）：Token 365 天后过期 ✅

### 2. 验证 Token 自动续期功能

**解决方案：** 排查确认 Token 续期功能已正确生效。当用户活跃使用页面时，Token 会在过期前自动续期，无需重新登录；仅当用户空闲超时后 Token 才过期，实现真正的超时登出。

**验证链路：**
- **后端中间件**：`TokenRefreshMiddleware` 在每次响应后检查 Token 剩余有效期，若小于 10 分钟阈值则生成新 Token
- **后端续期逻辑**：使用用户当前的 `session_timeout_minutes` 设置创建新 Token，确保续期后仍按用户配置的超时策略执行
- **响应传递**：新 Token 通过 `X-Refresh-Token` 响应头发送给前端
- **前端拦截器**：axios 响应拦截器读取 `x-refresh-token` 头，自动保存到 `localStorage`，后续请求使用新 Token

**验证结果：**
- 设置超时 5 分钟 → 登录后 Token 5 分钟过期 → API 调用时触发续期 → 收到 `X-Refresh-Token` 头 → 新 Token 剩余时间仍为 5 分钟 ✅
- 用户活跃 → API 持续调用 → Token 持续续期 → 无需重新登录 ✅
- 用户空闲 → 无 API 调用 → Token 过期 → 401 自动跳转登录页 ✅
