### 6. 投资复盘统计逻辑核验与边界修复

**解决方案：** 按规范逐项核验「相对首次买入 / 权重 / 贡献 / 卖飞 / 卖对 / 投资胜率 / 累计交易金额」的实现，发现两处偏差：① 卖对边界条件在 `卖出价 == 当前市场价` 时漏统计；② 投资胜率四舍五入到整数，与规范示例 66.7% 不一致。

**实现逻辑：**
- **后端 `hpi_service.py`**：
  - 卖对判断从 `current_price < sell_price` 修正为 `current_price <= sell_price`，使 `卖出价 == 当前市场价` 时正确归入"卖对"
  - 同步修正 components 中 `sell_right` 字段写入逻辑，与 sell_fly 互斥且能完整覆盖所有已出体
- **前端 `InvestmentReview.vue`**：
  - 投资胜率展示从 `Math.round` 整数百分比改为 `toFixed(1)` 一位小数（如 66.7%）
  - 投资胜率分母从 `soldUp + soldDown` 改为 `soldItems.length`（真正的已出体总数），与规范「卖对体数 / 已出体总数」一致

### 11. 修复 `/api/market/sector-ranking` 500 错误

**解决方案：** 后端遍历 `db.query(HPIComponent, ...)` 多实体查询结果时，误将 SQLAlchemy 2.x 的 `Row` 对象当作字典用 `row._mapping.get(dimension)` 访问，且 `isinstance(row, tuple)` 对 Row 恒为 False，导致 `comp` 仍是 Row 而非 `HPIComponent`，访问 `comp.weight` 抛 `AttributeError`。

**实现逻辑：**
- 统一通过 `row[0]` 取 `HPIComponent` 实例（Row 原生支持下标）
- 维度字段改用 `getattr(row, dimension, None)` 通过 labeled 列名取值
- 防御性加上 `getattr(comp, "weight", 0)` 兜底空值
- 兼容 SQLAlchemy 2.x 的 `Row` / `RowMapping` 行为差异

### 13. 投资复盘 - 成分股按 sold/holding 状态拆行展示

**解决方案：** 原投资复盘每个手办只展示一行，无法应对「同一手办买入多体，部分在柜、部分已出」的真实场景（如「桐宫美月 写实版」买入 3 体，1 体已出、2 体在柜）。参考 `hpi_redesign_v2.html` 投资复盘设计，将同一手办按状态拆分为 2 行展示（● 在柜·2体 / ● 已出·1体），让用户能清晰看到每个状态分片的收益、权重、贡献。

**实现逻辑：**

- **后端 `hpi_service.py`（企业级服务层）**：
  - `_get_sold_figure_map` 升级：返回 `{sell_price: 加权平均卖出价, sold_qty: 累计卖出体数}`，支持多笔卖出记录按体数加权
  - `_calculate_hpi` 重构：每只手办先计算「单体均价 unit_cost = 总买入金额 / 总买入体数」，再按 `sold_qty` / `holding_qty` 拆分为 0~2 行
    - 已出行：成本 = `unit_cost × sold_qty`，收益率 = `(sell_price - unit_cost) / unit_cost`
    - 在柜行：成本 = `unit_cost × holding_qty`，收益率 = `(current_price - unit_cost) / unit_cost`
  - 成本基准统一为「单体均价」，避免多笔不同价格买入时分片成本不一致
  - HPI 公式恒等：`Σ(权重) = 1`，`HPI = 1000 × (1 + Σ(权重×收益率)/100)` 保持不变
  - `total_figures / holding_figures / sold_figures` 改为「体数总和」而非「行数」，与设计稿「累计交易 N 体」语义一致
- **后端 `_get_today_components` / `get_components`**：天然支持返回多行（每行带 `is_sold` 区分），前端 `v-for` 直接渲染
- **后端 `_calculate_and_save`**：delete 逻辑不变（按 user_id + record_date 删全部），insert 循环天然支持多行
- **前端 `InvestmentReview.vue`（组件目录）**：
  - `v-for` key 改为 `${figure_id}-${is_sold ? 'sold' : 'holding'}` 避免重复 key
  - 状态徽标在 `quantity > 1` 时追加「· N体」后缀（如「● 在柜 · 2体」）
  - meta 文本根据 quantity 分支：单行显示「买入 ¥X → 现价 ¥Y」；多体显示「买入 ¥X/体 → 现价 ¥Y · 在柜 N体」
  - 卖出统计按「体」加权：`soldUp / soldDown / soldTotal` 使用 `c.quantity` 累加，确保投资胜率分母为「总卖出体数」
- 「累计交易金额」按行求和（拆行后总和不变，结果一致）
