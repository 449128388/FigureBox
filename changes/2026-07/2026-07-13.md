# 2026-07-13 更新日志

### 1. 修复后端容器连接 MySQL 被拒（1130 错误）

**解决方案：** 后端容器启动时报 `Host '172.26.0.4' is not allowed to connect to this MySQL server`，原因是 NAS 上 MySQL 数据目录持久化后，`admin` 用户未被授予 `%`（任意 IP）权限，Docker 网络中的后端容器被拒绝连接。

**实现逻辑：**

- **新建 `docker/mysql/init.sql`**：创建 SQL 文件，包含 `CREATE USER IF NOT EXISTS 'admin'@'%'` 和 `GRANT ALL PRIVILEGES ON figurebox.* TO 'admin'@'%'`，确保 admin 用户可从任意主机连接。
- **`docker-compose.yml`**：MySQL 启动命令增加 `--init-file=/etc/mysql/init.sql`，每次 MySQL 启动时自动执行 init.sql；新增 volume 挂载 `./docker/mysql/init.sql:/etc/mysql/init.sql:ro`。

### 2. 修复图片 URL 缺少端口号 28620

**解决方案：** 图片上传后返回的 URL 仅将 `localhost` 替换为 NAS 虚拟 IP，但缺少 `:28620` 端口号。原因有二：一是 Nginx 反代时将 `Host` 头转发为 `$host`（不含端口），后端收到 `100.111.216.7` 而非 `100.111.216.7:28620`；二是后端使用 `request.base_url` 取到的是 Uvicorn TCP 连接信息（内网 IP + 8000 端口），而非原始请求的域名和端口。

**实现逻辑：**

- **`frontend/nginx.conf`**：`proxy_set_header Host $host` 改为 `$http_host`，保留原始请求的 Host 头（含端口号）。
- **后端 `storage_service.py`**：`_build_public_url()` 改为读取 `request.headers` 中的 `x-forwarded-proto`（协议）和 `host`（域名+端口）动态构造 URL，格式为 `{scheme}://{host}/minio/{bucket}/{filename}`，确保端口号 28620 正确保留。
