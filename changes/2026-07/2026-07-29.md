## 架构优化

### 3. 合并手办标签双表为 figures 单表 JSON 字段

**解决方案：** 原手办标签由 `tags` 表（标签字典）和 `figure_tag` 关联表（手办-标签多对多关系）两张表共同维护，每次按标签筛选手办均需 JOIN 两表，IO 开销高；标签创建和绑定需跨表写入两次。考虑到标签本质上是手办的一个简单属性集合、多对多关系查询频次远低于单手办查询，改为在 `figures` 表新增 `tags` JSON 字段直接存储标签名称列表，旧 `tags` 与 `figure_tag` 表保留只读作为回滚缓冲。

**实现逻辑：**

- **数据迁移** `migrations/migrate_figure_tags_to_json.py`：在 `figures` 表新增 `tags` JSON 字段；将 `figure_tag + tags` 现有数据按 `figure_id` 聚合后写入 `figures.tags`，去重并以 JSON 数组形式存储；旧表保留不动

- **数据模型** `app/models/figure.py`：新增 `tags` JSON 字段，移除原 `figure_tag` 多对多关系

- **查询层** `figure_service/figure_query_service.py`：标签筛选由原 JOIN `figure_tag` 改为基于 `JSON_CONTAINS(Figure.tags, '"标签名"')` 的字段查询，支持多标签 AND 关系

- **CRUD 层** `figure_service/figure_crud_service.py` 与 `wishlist_service/wishlist_crud_service.py`：创建/更新手办时直接将 `tag_names` 列表写入 `figures.tags`，不再操作 `Tag` 中间模型

- **看板层** `api/collector/cabinets.py` 与 `collector_service/collector_activity_service.py`：修复工坊分类的标签匹配改为 `JSON_CONTAINS` OR 查询，移除对 `Tag` 模型和 `figure_tag` 表的依赖

- **采集层** `collector_service/collector_tag_service.py`：标签云统计改为查询 `figures.tags` JSON 字段并展开聚合

- **接口层** `api/figures.py` 与 `schemas/figure.py`：标签相关请求/响应模型从 `tag_ids`/`List[Tag]` 改为 `tag_names`/`List[str]`

- **导入层** `figure_service/figure_import_service.py`：导入数据时直接写入 `figures.tags` 字段

- **清理入口** `backend/entrypoint.sh`：删除 `python migrations/add_order_balance_payment_fields.py` 调用行，迁移链路最终态只保留 `add_all_table_comments.py` 一个脚本

### 14. 修复尾款管理已完成订单编辑时 asset_transactions 调整记录符号缺陷

**解决方案：** 已完成订单修改时，库存账 `asset_transactions` 表追加的 `adjust` 类型调整记录原本写入「调整后订单总成本（定金+尾款之和）」，而非「本次变更差额」，导致同一订单被多次编辑时库存账单价被反复覆盖为「最新全量成本」，与流水账口径不一致，无法通过求和反推原始 buy 记录的成本。修正后 `price` 与 `total_amount` 改为「本次变更人民币差额」（`new - old`，原生带符号：减少为负、追加为正），与 `notes` 中的「旧值 → 新值」描述一一对应，4 种变更组合（双减/双增/定增尾减/定减尾增）的符号方向均自动正确，不再需要 if/else 区分「追加/减少」。

**实现逻辑：**

- **修复定金变更** `services/order_service/order_crud_service.py`：删除「判断追加/减少」分支与「`total_cost_after_change = new_deposit_cny + new_balance_cny`」全量成本计算；将 `AssetTransaction.price` / `total_amount` 直接赋值为 `deposit_diff`（即 `new_deposit_cny - old_deposit_cny`）；`notes` 同步改为「定金调整导致的成本调整 (旧 → 新)」，不再带「追加/减少」文字（符号已隐含方向）

- **修复尾款变更** 同上，将 `price` / `total_amount` 直接赋值为 `balance_diff`；`notes` 改为「尾款调整导致的成本调整 (旧 → 新)」

- **4 种场景全部覆盖**：
  - 双减：`deposit_diff` / `balance_diff` 均为负 → 调整记录均为负数
  - 双增：均为正 → 均为正数
  - 定增尾减：定金正、尾款负 → 符号各自独立正确
  - 定减尾增：定金负、尾款正 → 符号各自独立正确

- **下游影响**：所有依赖 `asset_transactions` 的下游计算（资产仪表盘、日涨跌、收益曲线、HPI 指数、收藏家模式）现在可直接 `SUM(buy + Σadjust)` 还原单笔订单的真实累计成本，无需在下游再做差额二次计算
