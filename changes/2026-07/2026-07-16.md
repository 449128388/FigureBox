## 缺陷修复

### 1. 修复首页愿望清单数据不正确的缺陷

**解决方案：** 首页愿望清单统计仅计数 `wishlist_status` 为"wish"或"released"的记录，排除了已取消和已购买等状态的愿望清单项，导致计数低于实际总数。

**实现逻辑：**

- **后端 `home_service.py`**：`get_summary()` 的 `wishlist_count` 查询移除 `Figure.wishlist_status.in_(["wish", "released"])` 过滤条件，改为统计所有 `purchase_type == "wishlist"` 且 `is_active == 1` 的记录，与愿望清单页面统计口径一致。

### 2. 修复首页投资天数显示为 0 的缺陷

**解决方案：** 投资天数计算仅统计订单状态为"已完成"的记录，当用户首次下单后订单状态为"未支付"时无法计算出投资天数。

**实现逻辑：**

- **后端 `home_service.py`**：`get_summary()` 的 `invest_days` 查询移除 `Order.status == "已完成"` 过滤条件，改为统计所有 `is_active == 1` 的有效订单中最小 `created_at`，从首次下单日期开始计算投资天数。

### 3. 修复查看买入订单支付明细流水单号为 - 的缺陷

**解决方案：** 支付明细中的流水单号使用 `tx.order_id` 或固定 `-`，未展示 `orders` 表中的外部订单号。

**实现逻辑：**

- **后端 `buy_order_service.py`**：`_get_payment_details()` 提取公共变量 `order_no = order.order_number or order.display_order_number or "-"`，支付明细中所有条目（定金、尾款、全款及兜底填充）的 `transaction_no` 统一使用该变量，优先展示外部订单号。

## 新增功能

### 1. 尾款管理添加/编辑订单新增支付方式和支付时间字段

**解决方案：** 添加订单和编辑订单页面中尾款状态下缺少支付方式记录和支付时间记录功能，用户无法记录实际支付渠道和精确支付时间。

**实现逻辑：**

- **后端 `models/order.py`**：新增 `payment_method`（String(20)，支付方式：支付宝、微信、银行卡转账、现金）和 `payment_time`（DateTime，支付时间，精确到秒）两个字段。
- **后端 `schemas/order.py`**：在 `OrderBase`、`OrderCreate`、`OrderUpdate`、`Order`、`OrderListItem` 中均新增 `payment_method` 和 `payment_time` 字段声明（均为可选）。
- **后端 `migrations/add_order_payment_fields.py`**：新增迁移脚本，通过 `ALTER TABLE` 添加两列；`entrypoint.sh` 容器启动时自动执行该迁移。
- **前端 `OrderForm.vue`**：在"订单编号"与"订单备注"之间新增"支付方式"下拉选择框（支付宝/微信/银行卡转账/现金，可清除）和"支付时间"日期时间选择器（精确到秒，可清除）。
- **前端 `useOrderManagement.js`**：`newOrder` 默认数据和 `resetForm()` 中新增 `payment_method: ''` 和 `payment_time: ''` 初始值。

### 4. 修复 GET /api/orders/ 返回 502 的缺陷

**解决方案：** 迁移脚本 `add_order_payment_fields.py` 中 `from app.config import Config` 导致独立运行时报 `ModuleNotFoundError`，迁移未执行，数据库 `orders` 表缺少 `payment_method` 和 `payment_time` 列。SQLAlchemy 启动时模型声明包含这两列，查询时 MySQL 报列不存在错误，最终表现为 502。

**实现逻辑：**

- **后端 `migrations/add_order_payment_fields.py`**：将数据库配置读取方式从 `from app.config import Config` 改为 `os.getenv("DB_HOST")` 等环境变量读取，避免脚本独立运行时依赖应用模块。

### 5. 修复编辑订单时支付方式和支付时间未读取的缺陷

**解决方案：** 订单列表查询接口手动构建 `OrderListItem` 响应对象时漏掉了 `payment_method` 和 `payment_time` 字段，导致编辑表单填充时这两个字段为空。

**实现逻辑：**

- **后端 `order_query_service.py`**：`get_orders()` 的 `OrderListItem` 构造函数中新增 `payment_method=order.payment_method` 和 `payment_time=order.payment_time` 字段映射。

### 6. 修复查看买入订单支付明细中支付方式未使用 orders 表数据的缺陷

**解决方案：** 支付明细中的"支付方式"使用 `tx.payment_method`（资金流水记录的支付方式）或固定 `-`，未展示 `orders` 表中用户填写的支付方式。

### 17. 企业级组件拆分重构——OrderForm 三步弹窗

**解决方案：** 原有的 `OrderForm.vue` 是一个单体组件，包含弹窗外壳、三个步骤的全部表单字段、步进器 UI、步骤切换逻辑等，代码耦合度高、难以维护。按照企业级 Vue3 组件拆分规范，进行单一职责拆分。

**实现逻辑：**

- **目录结构变更**：
  ```
  Orders/components/
    OrderForm.vue                        ← 弹窗外壳（保留原入口）
    OrderFormSteps/
      Step1CoreInfo.vue                  ← 步骤1：核心信息子表单
      Step2ShopPayment.vue               ← 步骤2：店铺与支付子表单
      Step3LogisticsNotes.vue            ← 步骤3：物流与备注子表单
    OrderFormUI/
      AmountStepper.vue                  ← 通用金额步进器UI组件
  Orders/composables/
    useStepForm.js                       ← 已有：步骤导航逻辑
    useOrderAmount.js                    ← 新增：金额调整与币种选项
  ```

- **数据流规范（props 向下、emit 向上）**：
  - `OrderForm.vue` 作为唯一数据源持有 `newOrder` 对象，接收父组件传递的 `availableFigures`、`figureError`、`dueDateError` 等
  - 各子步骤组件通过 `v-model:fieldName` 模式接收字段值 prop，通过 `update:fieldName` 事件通知父组件更新
  - 子组件禁止直接修改父数据，所有变更通过 emit 向上冒泡

- **分层职责**：
  - `OrderForm.vue`：弹窗蒙层/卡片容器、头部标题/关闭按钮、步骤进度条、左侧步骤导航栏、底部操作栏（取消/上一步/下一步/保存）、步骤切换校验入口
  - `Step1CoreInfo.vue`：手办选择、定金/尾款金额步进器、出荷日期、订单类型、尾款状态及字段错误提示
  - `Step2ShopPayment.vue`：购买店铺、店铺联系方式、支付方式、支付时间
  - `Step3LogisticsNotes.vue`：条件渲染的物流信息与尾款支付信息（根据 status 判断）、订单编号、订单备注
  - `AmountStepper.vue`：封装−/+步进按钮 + 币种下拉的通用金额输入组件，支持 `modelValue`/`currencyModelValue` 双向绑定

### 18. 修复订单表单三步向导交互缺陷

**解决方案：** 三步向导存在 3 处交互缺陷,影响添加/编辑订单的正常使用:① 每次打开弹窗未做步骤重置,残留上次的步骤位置 ② 步骤 1 必填未填写时步骤 3 不可点,但已填写后也无清晰的可达性视觉提示 ③ 「下一步」按钮在校验失败时静默 return,无任何反馈。

**实现逻辑：**

- **修复 1 — 弹窗打开重置步骤（`OrderForm.vue`）**：
  - 新增 `watch.visible` 监听,visible 变为 true 时调用 `resetStep()` 重置到步骤 1
  - 保证每次进入添加/编辑订单都是干净的初始步骤位置,不会保留上次的步骤状态

- **修复 2 — 步骤可达性控制（`useStepForm.js` + `OrderForm.vue`）**：
  - `useStepForm.js` 扩展 `goToStep` 与新增 `canJumpTo`,接受外部传入的 `reachableSteps` 参数
  - 跳转到更远步骤时校验 `[currentStep+1, target]` 区间内所有步骤是否在可达集合内
  - `OrderForm.vue` 新增 `isStep1Valid` computed（手办必填、尾款状态非「已取消」时出荷日期必填）
  - 新增 `reachableSteps` computed: 步骤 1 校验通过 → `{1,2,3}` 全可达;否则仅 `{1,2}`
  - 步骤导航新增 `disabled` class,不可达步骤降低透明度、`cursor: not-allowed`
  - 点击未达步骤时 `emit('validateStep', 1)` 触发父组件校验,显示错误提示
  - 必填填写完成后,步骤 1、3 可自由点击切换

- **修复 3 — 下一步按钮反馈（`OrderForm.vue` + `Orders.vue`）**：
  - `OrderForm.vue` 的 `handleNext` 在步骤 1 时先 `emit('validateStep', 1)` 通知父组件
  - 父组件 `Orders.vue` 新增 `handleValidateStep` 处理器,调用 `validateForm()` 触发 `figureError`/`dueDateError` 的赋值
  - 由于 `OrderForm` 通过 props 接收 `figureError`/`dueDateError` 并透传给 `Step1CoreInfo`,用户未填时点击「下一步」会立即看到字段下方的红色错误提示
  - 校验未通过时不调用 `nextStep()`,停留在原步骤;校验通过才前进

- **`useStepForm.js` 接口扩展**:
  - 保留原 `goToStep(step)` 单参调用兼容老代码
  - 新增 `canJumpTo(target, reachableSteps)` 单独返回布尔,供模板计算 class 使用
