# 2026-04-27 更新日志

## 持仓列表新增补仓功能

### 问题背景
用户需要在持仓列表中直接执行补仓操作，以便在看好某个手办时快速加仓，同时系统需要正确处理补仓后的成本计算、库存更新和财务记录。

### 解决方案

**1. 前端实现**
在持仓列表的每个手办卡片操作菜单中添加"补仓"选项，点击后弹出补仓对话框：
- 展示当前持仓信息（数量、成本价、当前市值）
- 输入补仓数量和补仓价格
- 实时预览补仓后的加权平均成本价和总库存
- 确认后执行补仓操作

**组件结构：**
- AddPositionDialog.vue - 补仓弹窗组件
- useAddPosition.js - 补仓业务逻辑composable

**2. 后端实现**
创建补仓服务AddPositionService，执行以下操作：
- 创建已完成状态的订单（补仓视同已完成购买）
- 创建asset_transactions记录（买入类型）
- 创建order_transactions记录（资金流出）
- 更新手办数量（原数量 + 补仓数量）
- 重新计算加权平均成本价
- 更新日涨跌缓存（新买入部分按买入价=市值处理）

**服务架构：**
- add_position_service.py - 补仓服务
- assets.py API - 补仓接口

**3. 核心计算逻辑**

**加权平均成本价计算：**
```
新成本价 = (原成本 × 原数量 + 补仓价格 × 补仓数量) / (原数量 + 补仓数量)
```

**日涨跌处理（市值法）：**
- 新买入部分按买入价计入今日市值
- 当日涨跌 = (原市值 + 新买入市值) - 昨日市值
- 新买入部分对当日涨跌贡献为0
- 只有原有持仓部分产生涨跌波动

### 关联数据变更
1. 尾款管理新增"已完成"状态的补仓订单
2. asset_transactions表新增买入记录
3. order_transactions表新增资金流出记录
4. 手办详情中的平均入手价格重新计算
5. 手办数量相应增加
6. 总资产增加，仓位相应变化

### 实现效果
- ✅ 持仓列表支持补仓操作
- ✅ 补仓后成本价自动加权平均计算
- ✅ 补仓订单自动同步到尾款管理
- ✅ 财务记录完整（资金账+库存账）
- ✅ 日涨跌计算正确处理（新买入部分贡献0%波动）
- ✅ 前端组件分离，业务逻辑抽离到composable
- ✅ 后端采用企业级服务层架构

## 补仓功能币种选择

### 问题背景
用户需要在补仓时支持多种币种选择，系统根据汇率自动转换为人民币计算补仓后成本。

### 解决方案

**汇率配置：**
```javascript
EXCHANGE_RATES = {
  'CNY': 1.0,    // 人民币
  'JPY': 1/23,   // 日元：1人民币 = 23日元
  'USD': 7.0,    // 美元：1美元 = 7人民币
  'EUR': 8.0     // 欧元：1欧元 = 8人民币
}
```

**1. 补仓页面（AddPositionDialog.vue）**
- 在补仓价格输入框后添加币种选择器（el-select）
- 支持币种：CNY、JPY、USD、EUR
- 默认币种为人民币（CNY）

**2. 补仓逻辑（useAddPosition.js）**
- 添加汇率配置和 `convertToCNY` 转换函数
- 在计算补仓后成本时，先将补仓价格按汇率转换为人民币
- 补仓后成本计算公式：`(原成本 × 原数量 + 补仓价格(人民币) × 补仓数量) / (原数量 + 补仓数量)`
- 提交时发送转换后的人民币价格和币种信息给后端

### 实现效果
- ✅ 补仓页面支持币种选择（CNY/JPY/USD/EUR）
- ✅ 根据汇率自动转换补仓价格为人民币
- ✅ 补仓后成本按人民币统一计算
- ✅ 补仓提交包含币种信息
