## 缺陷修复 → 18. 密码重置-StaleDataError 导致重置失败

**解决方案：** 用户在「重置密码」步骤 2 输入新密码点击「确认重置」后，后端抛出 `sqlalchemy.orm.exc.StaleDataError: UPDATE statement on table 'password_reset_codes' expected to update 1 row(s); 0 were matched.`，前端展示「密码重置失败，请稍后重试」。**根因**：[password_reset_service.py:226-239](file:///e:/项目编写/项目编写/FigureBox/backend/app/services/auth_service/password_reset_service.py#L226-L239) `reset_password` 方法在 4 步操作中存在**逻辑顺序 bug** — 步骤 1 标记 `record.is_used = 1`（仅在 Python ORM 内存中变更，**未 flush**）→ 步骤 2 `db.query(...).filter(email, is_used=0).delete()` 在数据库中执行 DELETE，但因为 `is_used` 还没写入数据库，过滤条件 `is_used=0` **仍然匹配当前 record** → record 被一起删除 → 步骤 3 `db.commit()` 时 SQLAlchemy 试图把内存中的 `is_used = 1` UPDATE 写入数据库，但该行已被 DELETE 删了 → **StaleDataError**。修法：**先 `db.flush()` 强制把 `is_used=1` 写入数据库（使 DELETE 过滤条件不再匹配 record）** + **DELETE 时额外加 `id != record.id` 防御性过滤**（即使 flush 失败也不会删掉 record）。

**实现逻辑：**

- **【#18 阶段 1】[password_reset_service.py](file:///e:/项目编写/项目编写/FigureBox/backend/app/services/auth_service/password_reset_service.py#L226-L242) `reset_password` 关键 3 行修改**：
  - 原值：标记 → delete（无 flush）→ commit
    ```python
    user.password_hash = get_password_hash(new_password)
    record.is_used = 1
    db.query(...).filter(email, is_used=0).delete(synchronize_session=False)
    db.commit()
    ```
  - 新值：标记 → **flush** → delete（**+ id 排除**）→ commit
    ```python
    user.password_hash = get_password_hash(new_password)
    record.is_used = 1
    db.flush()  # 关键：先 flush 标记操作到 DB
    db.query(...).filter(email, is_used=0, id != record.id).delete(synchronize_session=False)
    db.commit()
    ```
