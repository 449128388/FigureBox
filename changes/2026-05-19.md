2. 修复 `Dashboard.vue`：在 `return` 语句中添加 `handleMonthChange`，确保方法可被模板调用

- `TradeView` 监听事件并转发给 `Dashboard` 的 `handleMonthChange`
- `Dashboard` 的 `handleMonthChange` 更新 `selectedMonth` 状态并调用 `fetchTradeData()` 请求后端数据

#### 关键修复点
- `TradeView.vue:90`: `setup(props)` → `setup(props, { emit })`
- `Dashboard.vue:618`: 在 `return` 对象中添加 `handleMonthChange`
- 移除 `MonthSelector.vue`、`TradeView.vue`、`Dashboard.vue` 中的调试日志

#### 问题描述

`BillExportService.py` 中使用了与模型字段不匹配的属性名，导致 `AttributeError`：

6. `so.profit` → SoldOrder模型实际字段为 `net_profit`
7. `so.platform` → SoldOrder模型实际字段为 `sell_platform`
8. `so.notes` → SoldOrder模型实际字段为 `remark`
9. `_format_transactions` 方法接收了未使用的 `db` 参数

#### 解决方案
修正 `BillExportService.py` 中所有与模型不匹配的字段引用：
- 根据实际模型定义修正 `_get_transactions` 方法中的所有字段名
- 移除未使用的 `Order` 模型导入
- 移除 `_format_transactions` 方法中未使用的 `db` 参数

- OrderTransaction 记录：`illustrator` → `original_art`，`order.purchase_type` → `figure.purchase_type`
- SoldOrder 记录：`sold_date` → `created_at`，`sold_price` → `sell_price`，`profit` → `net_profit`，`platform` → `sell_platform`，`notes` → `remark`，`total_amount` 改为手动计算

| 指标 | 定义 |
| ---- | ---- |
| 本年实现收益 | 本年度所有卖出交易的盈亏总和 |
| 本年交易胜率 | 盈利卖出笔数 ÷ 总卖出笔数 |
| 平均盈利 | 盈利卖出的单笔平均收益 |
| 平均亏损 | 亏损卖出的单笔平均亏损（绝对值） |

   - 按自然年筛选：使用 `extract('year', SoldOrder.created_at)` 筛选本年度数据
   - 成本数据缺失处理：成本为 None 或 ≤0 时跳过该笔统计
   - 盈亏为0处理：不计入胜率统计（平局）
   - 退货/退款处理：查询 `OrderTransaction` 表中 `transaction_type = 'REFUND'` 的记录，从本年统计中扣减

2. **前端组件修改**：
   - 今年无卖出时显示 `--` 或 `0% (0胜0负)`
   - 添加 `hasTradeData` 计算属性判断是否有交易数据
   - 添加 `neutral` 样式用于无数据状态显示

#### 实现逻辑
- 时间维度：按自然年统计（当年1月1日至今）
- 成本缺失：单笔盈亏无法计算时跳过，不纳入统计
- 盈亏为0：平局不影响胜率计算
- 退货/退款：生成反向流水，从本年收益中扣减

#### 涉及文件
- `backend/app/services/dashboard_service/trade_records_service/profit_analysis_service.py`: 完善盈亏分析逻辑

### 修复手办导入时 asset_transactions 表 created_at 为空的问题

#### 问题描述
在手办管理中进行手办导入成功后，查看数据库发现 `asset_transactions` 表中 `created_at` 字段数据为空。

#### 根因分析
虽然 `AssetTransaction` 模型定义中 `created_at` 字段使用了 `server_default=func.now()`，但在某些数据库配置或 SQLAlchemy 版本中，如果不在代码中显式设置 `created_at`，可能会导致该字段为空。所有创建 `AssetTransaction` 对象的地方都没有显式设置 `created_at` 和 `updated_at` 字段。

#### 解决方案
在所有创建 `AssetTransaction` 对象的地方，显式添加 `created_at` 和 `updated_at` 字段赋值。

#### 实现逻辑
- 统一使用 `now = datetime.now()` 获取当前时间
- 在创建 `AssetTransaction` 对象时，显式设置 `created_at=now` 和 `updated_at=now`
- 同时设置 `transaction_date` 为当前时间

#### 涉及文件
- `backend/app/services/asset_transaction_service/asset_transaction_create_service.py`: 所有创建资产交易记录的方法（create_transaction_from_figure、create_sell_transaction、create_buy_transaction_from_order、create_quantity_adjustment_transaction、create_price_adjustment_transaction）
- `backend/app/services/order_service/order_crud_service.py`: 订单定金和尾款变更时创建调整交易记录
- `backend/app/services/dashboard_service/assets_service/add_position_service.py`: 补仓创建资产交易记录
- `backend/app/services/sold_order_service/sold_order_inventory_service.py`: 卖出订单创建库存扣减交易记录

#### 结果
所有创建 `AssetTransaction` 记录的地方都显式设置了 `created_at` 和 `updated_at` 字段，确保时间戳数据正确记录。

### order_transactions 表新增 sold_order_id 字段

#### 需求描述
在 `order_transactions` 表新增 `sold_order_id` 字段，用于将资金流水记录与 `sold_orders` 表关联起来。

#### 解决方案
1. **模型修改**：
   - 在 `OrderTransaction` 模型中添加 `sold_order_id` 字段（外键关联 `sold_orders.id`）
   - 添加 `sold_order` 关系属性

2. **数据库迁移**：
   - 创建迁移脚本添加 `sold_order_id` 字段
   - 可选添加外键约束

3. **服务层修改**：
   - 修改 `sold_order_transaction_service.py`：在创建卖出交易记录时设置 `sold_order_id`
   - 包括：卖出收入、运费支出、平台手续费支出

#### 实现逻辑
- 当创建已出售订单时，自动创建 `OrderTransaction` 记录，并关联 `sold_order_id`
- 外键关系：`order_transactions.sold_order_id` → `sold_orders.id`
- 通过关联可以方便地查询某个卖出订单对应的所有资金流水记录

#### 涉及文件
- `backend/app/models/asset.py`: 新增 `sold_order_id` 字段和关系
- `backend/migrations/add_sold_order_id_to_order_transactions.py`: 数据库迁移脚本
- `backend/app/services/sold_order_service/sold_order_transaction_service.py`: 创建交易记录时设置 `sold_order_id`

#### 结果
`order_transactions` 表新增 `sold_order_id` 字段，实现与 `sold_orders` 表的关联，支持精确追踪卖出订单的资金流水记录。
