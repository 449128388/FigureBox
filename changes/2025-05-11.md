# 2025-05-11 更新日志

## 补仓功能交易记录优化

### 需求背景
在用户进行多数量的补仓操作时，order_transactions 和 asset_transactions 应该生成对应条数的数据，以便将补仓数据与订单 order_id 进行一对一关联。

### 解决方案
- 将订单交易记录创建方法改为批量生成模式，每条订单对应生成一条 order_transaction 记录
- 将资产交易记录创建方法改为批量生成模式，每条订单对应生成一条 asset_transaction 记录
- 修改补仓操作返回结果，返回 ID 列表而非单个 ID

### 实现效果
- ✅ 补仓 N 体手办时，生成 N 条订单记录及对应的交易记录
- ✅ 实现交易记录与订单的一对一关联，便于追踪和管理

### Bug修复

#### 后端500错误修复
- **问题**：GET `/api/sold-orders/` 返回500 Internal Server Error
- **原因**：`sold_order_query_service.py` 中使用了 `Figure.image_url` 字段，但Figure模型中实际字段名为 `images`（JSON数组）
- **解决方案**：修改查询逻辑，使用 `Figure.images` 字段，并提取第一个图片URL作为 `figure_image`

#### 前端表单字段修复
- **问题**：选择手办后成本价无法自动带出
- **原因**：`handleFigureChange` 函数中使用了不存在的 `figure.purchase_price` 字段
- **解决方案**：修改为使用正确的字段名 `figure.average_purchase_price`

#### 添加卖出按钮无反应修复
- **问题**：点击"添加卖出"按钮没有反应，没有接口响应，也没有表单页面出现
- **原因**：SoldOrderForm.vue 中 el-dialog 组件使用了 `:visible="visible"` 属性绑定，但在当前 Element Plus 版本中应该使用 `v-model="visible"` 来控制对话框显示状态
- **解决方案**：将 `:visible="visible"` 修改为 `v-model="visible"`，使对话框能够正确响应 visible 属性的变化
