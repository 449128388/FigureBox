## 修复补仓订单支付明细展示问题

### 问题描述
当订单类型是"补仓"时，支付明细中错误地展示了定金和尾款，而补仓订单应该只展示全款支付记录。

### 解决方案
在 `buy_order_service.py` 的 `_get_payment_details` 方法中添加订单类型判断，当订单类型为"补仓"时跳过定金和尾款的拆分逻辑及默认条目添加。

### 实现逻辑
1. **问题根因**：原代码中所有订单类型都会执行定金和尾款的拆分逻辑，没有区分补仓订单
2. **修复方案**：
   - 在方法开头获取订单类型，判断是否为"补仓"
   - 当订单类型为"补仓"时：
     - 跳过定金+尾款拆分逻辑（不将"buy"类型拆分为定金和尾款）
     - 跳过默认定金和尾款条目添加
     - 跳过已取消订单状态修正（补仓订单不会被取消为这种状态）
     - 跳过定金尾款排序逻辑
3. **代码位置**：`backend/app/services/dashboard_service/trade_records_service/buy_order_service.py`

### 结果
- 补仓订单支付明细只展示全款记录
- 其他订单类型（预定、全款预定、现货、已取消预定）保持原有逻辑不变

## 交易流水查询索引优化

### 问题描述
交易流水（按时间倒序）查询功能在数据量增大时响应速度变慢，需要建立数据库索引提升查询性能。

### 解决方案
为交易流水查询涉及的时间字段建立复合索引，优化按时间倒序查询的性能。

### 实现逻辑
1. **索引设计**：
   - `idx_sold_orders_user_created_at`：sold_orders 表的 user_id + created_at(DESC) 复合索引，用于卖出交易流水按时间倒序查询
   - `idx_orders_user_created_at`：orders 表的 user_id + created_at(DESC) 复合索引，用于买入交易流水按时间倒序查询
   - `idx_asset_transactions_user_date`：asset_transactions 表的 user_id + transaction_date(DESC) 复合索引，用于资产交易记录按时间倒序查询
   - `idx_order_transactions_user_date`：order_transactions 表的 user_id + transaction_date(DESC) 复合索引，用于订单交易流水按时间倒序查询
   - `idx_sold_orders_user_status_active`：sold_orders 表的 user_id + status + is_active 复合索引，用于筛选已完成且未删除的卖出订单
   - `idx_orders_user_status_active`：orders 表的 user_id + status + is_active 复合索引，用于筛选未删除的买入订单

2. **架构特点**：
   - 复合索引设计：用户ID作为前缀，支持用户隔离查询
   - 时间倒序索引：created_at 和 transaction_date 使用 DESC 排序，符合交易流水按时间倒序展示的业务需求
   - 状态索引：支持按订单状态和软删除标记快速筛选

3. **代码位置**：
   - `backend/migrations/add_trade_records_indexes.py`

### 结果
- 交易流水按时间倒序查询性能显著提升
- 支持用户ID+时间的复合查询优化
- 支持订单状态和软删除标记的快速筛选

## 修复交易流水无数据问题

### 问题描述
交易流水（按时间倒序）模块显示无数据，卖出订单记录无法展示。

### 解决方案
移除卖出订单查询中的状态限制，由前端筛选处理状态过滤，同时修复状态字段显示逻辑。

### 实现逻辑
1. **问题根因**：
   - 卖出订单查询时限定只查询 `status == "已完成"` 的订单
   - 但前端状态筛选支持多状态（已完成、待发货、已发货、已取消等）
   - 状态字段被硬编码为"✅ 成功"，不显示实际订单状态

2. **修复方案**：
   - 移除 `_get_aggregated_sell_records` 方法中的 `SoldOrder.status == "已完成"` 查询条件
   - 改为查询所有未删除的卖出订单，状态筛选由前端处理
   - 将状态字段从硬编码 `"✅ 成功"` 改为 `so.status or "待发货"`，显示实际订单状态

3. **代码位置**：
   - `backend/app/services/dashboard_service/trade_records_service/transaction_query_service.py`

### 结果
- 交易流水正常显示所有卖出订单记录
- 订单状态根据实际数据动态显示
- 前端状态筛选功能正常工作

## 修复交易流水默认只展示卖出数据问题

### 问题描述
交易流水（按时间倒序）在不查询的情况下只展示【卖出】的数据，默认应该展示全部流水数据（买入和卖出）。

### 解决方案
修改前端默认筛选参数，将状态列表默认值从 `['已完成']` 改为空数组 `[]`，不默认筛选任何状态。

### 实现逻辑
1. **问题根因**：
   - `TradeFlow.vue` 和 `TradeFlowFilter.vue` 中的 `statusList` 默认值为 `['已完成']`
   - 这导致页面加载时只查询状态为"已完成"的订单
   - 买入订单和卖出订单中不是"已完成"状态的记录被过滤掉

2. **修复方案**：
   - 将 `TradeFlow.vue` 中的 `statusList` 默认值从 `['已完成']` 改为 `[]`
   - 将 `TradeFlowFilter.vue` 中的 `statusList` 默认值和重置值从 `['已完成']` 改为 `[]`
   - 将 `Dashboard.vue` 中的 `statusList` 默认值从 `['已完成']` 改为 `[]`
   - 空数组表示不筛选状态，展示全部流水数据

3. **代码位置**：
   - `frontend/src/views/Dashboard/components/reseller/trade/TradeFlow.vue`
   - `frontend/src/views/Dashboard/components/reseller/trade/TradeFlowFilter.vue`
   - `frontend/src/views/Dashboard.vue`

### 结果
- 页面默认展示全部交易流水数据（买入和卖出）
- API 请求参数中不再默认包含 `status_list=已完成`
- 用户可以通过筛选面板选择特定状态进行过滤
- 重置筛选后恢复展示全部数据
