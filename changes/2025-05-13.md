## 修复库存账卖出交易记录错误

### 问题描述
当手办发生卖出后，库存账（asset_transactions）记录错误：
- 卖出交易的 `price` 和 `total_amount` 字段记录的是卖出价，而不是出库成本
- 这违背了库存账的职责，库存账只负责记录资产数量的增减和对应成本

### 解决方案
修改 `AssetTransactionCreateService.create_sell_transaction` 方法：
1. 使用 FIFO（先进先出）算法计算出库成本
2. 遍历买入记录，按时间顺序扣减库存并累加成本
3. 卖出交易记录的 `price` 字段记录 FIFO 平均出库成本单价
4. 卖出交易记录的 `total_amount` 字段记录 FIFO 出库总成本

### 实现逻辑
- 在扣减库存前，先遍历买入记录计算出库总成本
- 使用 `buy_tx.price * deduct_amount` 累加每笔出库的成本
- 计算平均出库成本单价：`total_cost / quantity`
- 创建卖出交易时使用计算得到的成本价，而非传入的卖出价

### 修复后效果
- 库存账正确记录出库成本，符合财务记账原则
- 卖出价应记录在资金账（OrderTransaction）中，与库存账职责分离
- 确保资产估值和盈亏计算的准确性

## 修复持仓列表成本计算错误

### 问题描述
持仓列表（按盈亏排序）中的成本计算错误：
- 当前使用 `figure.average_purchase_price`（手办模型中的静态字段）作为成本
- 该字段是静态的，不会反映卖出后的实际剩余持仓成本
- 导致卖出后持仓列表显示的成本和盈亏计算不正确

### 解决方案
修改 `HoldingPositionService.build_holding_detail` 方法：
1. 新增 `calculate_remaining_cost_price` 方法，从库存账计算当前剩余持仓的实际平均成本
2. 使用该方法替代原有的静态字段获取方式

### 实现逻辑
- 查询该手办的所有买入记录（transaction_type='buy'）
- 基于 `remaining_quantity` 和 `price` 计算剩余持仓的总成本
- 平均成本 = 剩余总成本 / 剩余总数量
- 如果没有库存，返回手办的平均入手价作为备选

### 修复后效果
- 卖出后，剩余持仓的成本基于未卖出部分重新计算
- 确保持仓列表显示的成本和盈亏计算准确
- 符合财务记账原则，正确反映实际持仓成本

## 修复持仓列表盈亏计算错误

### 问题描述
持仓列表（按盈亏排序）中的盈亏计算错误：
- 当前只计算了单个体的盈亏（`profit = current_price - cost_price`）
- 没有考虑库存数量，导致当库存大于1时盈亏计算不正确
- 卖出后库存减少，但盈亏没有相应调整

### 解决方案
修改 `HoldingPositionService.build_holding_detail` 方法：
1. 调整代码顺序，先获取库存数量
2. 计算总盈亏：`profit = (current_price - cost_price) * stock`
3. 盈亏比例仍基于单价计算：`profit_percentage = (unit_profit / cost_price * 100)`

### 实现逻辑
- 单价盈亏 = 当前市场价 - 成本价
- 总盈亏 = 单价盈亏 × 库存数量
- 盈亏比例 = (单价盈亏 / 成本价) × 100%
- 库存数量从库存账（AssetTransaction）获取，卖出后自动减少

### 修复后效果
- 盈亏计算正确反映实际持仓价值
- 卖出后库存减少，总盈亏也相应减少
- 盈亏排序更加准确，符合实际投资盈亏情况

## 修复总资产/仓位统计错误

### 问题描述
卖出手办后，总资产和仓位统计不正确：
- 总资产计算使用 `figure.quantity`（手办模型中的静态字段），不会反映卖出后的实际库存变化
- 仓位计算（已投入成本）同样使用静态字段，没有从库存账获取真实数据
- 导致卖出后总资产和仓位仍然显示卖出前的数值

### 解决方案
1. 在 `TotalAssetsCalculator` 中新增 `calculate_from_transactions` 方法：
   - 从库存账（AssetTransaction）获取每个手办的实际剩余库存
   - 乘以对应手办的当前市场价计算总资产
   
2. 在 `PositionCalculator` 中新增 `_calculate_invested_cost_from_transactions` 方法：
   - 从库存账获取剩余库存和对应成本
   - 卖出后已投入成本相应减少

3. 在 `AssetCalculationService` 中新增 `calculate_total_assets_from_transactions` 方法

### 实现逻辑
- **总资产计算**：总资产 = Σ(手办市场价 × 剩余库存数量)
- **已投入成本**：已投入成本 = Σ(剩余数量 × 成本价)
- **仓位计算**：仓位 = 已投入成本 / 投资预算上限 × 100%

### 修复后效果
- 卖出手办后，总资产和仓位统计正确更新
- 符合实际投资场景，卖出后资产减少
- 保持向后兼容性，原有接口不受影响
