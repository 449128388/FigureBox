## 修复 asset_transactions 卖出记录 price 不符合 FIFO 规则

### 问题描述
持仓列表快速卖出后，`asset_transactions` 产生的卖出记录中 `price` 数值不符合 FIFO（先进先出）规则。

### 解决方案
修改 `sold_order_inventory_service.py` 中的 `deduct_inventory` 方法：
1. 调整执行顺序：先执行 FIFO 库存扣减，在扣减过程中累加实际买入价格，最后创建卖出记录
2. FIFO 成本计算：按时间排序获取买入记录，扣减时记录每条买入记录的价格和扣减数量
3. 卖出记录创建：使用 FIFO 单价作为 price，使用 FIFO 总成本作为 total_amount

### 实现逻辑
- **FIFO 规则**：先进先出，先买入的先卖出
- **价格来源**：使用实际买入记录的 price 字段，而非加权平均成本
- **成本计算**：根据实际扣减的买入记录逐条计算
- **数据追溯**：备注中记录扣减的买入记录 ID 和价格，便于审计

## 修改总资产计算方法为基于已完成订单（扣除已出售数量）

### 问题描述
原总资产计算未考虑已出售订单的影响，当手办在已出售订单中卖出后，总资产统计的手办数量没有相应减少。

### 解决方案
修改 `calculate_by_orders` 方法，在计算总资产时扣除已出售订单中的数量。

### 实现逻辑
- **数据来源**：
  - 已完成订单：尾款管理中状态为"已完成"的订单
  - 已出售订单：`sold_orders` 表中 `is_active=True` 的记录
- **计算步骤**：
  1. 按手办 ID 分组统计已完成订单数量
  2. 按手办 ID 分组统计已出售订单数量
  3. 计算剩余数量 = 已完成订单数量 - 已出售数量
  4. 计算总市值：`Σ(手办市场价 × 剩余数量)`
- **特点**：卖出后总资产相应减少，准确反映实际持仓市值

## 新增资产缓存定时任务

### 问题描述
`asset_value_cache` 表的数据保存是被动触发的（访问资产看板时），如果用户不每天访问资产看板，表中会出现日期断层，导致收益曲线出现断点。

### 解决方案
创建定时任务调度器，每天晚上北京时间23:30自动保存所有用户的总资产到 `asset_value_cache` 表。

### 实现逻辑
- **调度器**：使用 APScheduler 库创建后台定时任务调度器，时区设置为北京时间（Asia/Shanghai）
- **执行时间**：每天晚上北京时间23:30
- **执行逻辑**：
  1. 获取所有用户
  2. 对每个用户计算当前总资产（基于已完成订单，扣除已出售数量）
  3. 保存到 `asset_value_cache` 表
- **启动方式**：应用启动时自动启动调度器
- **容错处理**：单个用户保存失败不影响其他用户
