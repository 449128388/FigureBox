## 4. 接口拆分优化（单一职责原则）

### 需求背景
原接口 `GET /api/trade_records/dashboard` 一次性返回月度汇总统计、交易明细列表、利润分析、查询筛选参数四块大体积数据，返回体臃肿、查询慢、前端按需加载浪费带宽

### 解决方案
按单一职责原则拆分为3个独立GET接口，共用同一套请求参数

### 实现逻辑

**后端拆分：**
- `GET /api/trade_records/monthly-stats` - 获取月度汇总统计
  - 返回：买入统计、卖出统计、费用统计、净收支
  - 参数：year, month

- `GET /api/trade_records/transactions` - 获取交易明细列表
  - 返回：买入交易记录、卖出交易记录、费用流水记录
  - 参数：year, month, filter_type, time_type, date_start, date_end, figure_ids, platforms, status_list, min_amount, max_amount, keyword

- `GET /api/trade_records/profit-analysis` - 获取利润分析数据
  - 返回：年度总览、月度趋势、图表数据
  - 参数：year, month

**前端优化：**
- 使用 `Promise.all` 并行请求三个接口
- 拼装接口返回数据，保持原有数据结构兼容
- 提升页面加载速度，减少不必要的带宽消耗

### 结果
- 接口职责单一，便于维护和扩展
- 前端按需加载，减少首屏加载时间
- 并行请求提升数据获取效率
